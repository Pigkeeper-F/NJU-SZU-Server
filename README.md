# 研序 · 研究工作台

维护入口：[工程架构速查](docs/architecture.md)——职责、执行能力、代码入口、数据保存位置与常见问题定位；架构相关改动同步更新。

数据清洗已接入固定CSV/TSV/Excel检查、确认规则后的冻结脚本执行、独立核验和原脚本复现，操作与限制见[清洗模块说明](docs/cleaning.md)。

本仓库合并了本地研序交接版与 GitHub `origin/main` 的工作流改动。主界面按资料准备和模型工作组织：下载数据、数据清洗、文献挖掘是三条并列准备路径，按任务需要汇入“模型调整与计算”；后续为绘图、结果核查与定位、人工审核。三个准备环节可独立开展，不要求依次完成；参数与活动数据更新是计算的可选子环节。SOC 流水线位于 `SOC-database-pipeline-clean/`，复用其 Google Scholar 候选发现能力；网页通用文献流程另支持开放全文获取、带出处提取与清洗交接，尚未接入 SOC 专用数据库的自动合并。

默认界面使用固定七模块工作台，九步研究流程暂不展示；旧任务与记录保留，兼容入口见下文。2026-10-23 已同步双方融合后的主分支，并补齐导入、调研和旧任务兼容检查，见[融合验证记录](docs/merge-20261023.md)。

失败与未完成记录也随案例提供：[历史任务快照](examples/failed-task-records-20261023/README.md)，包含 5 条失败/停止/待讨论记录及 10 条历史事件。原消息和当前状态分别保留，正常人工确认不会算成故障；已删除任务不重新公开。

## 启动

安装 Node.js 18+ 后，在本目录运行 `npm start`，访问 `http://localhost:8123/`。Windows 可双击 `start-workbench.cmd`（端口 18125）。项目使用 Node 内置模块，无需 `npm install`。不要直接双击 `index.html` 使用 AI、文件上传和执行功能；服务只监听本机。

启动器会核对当前后台版本，同版本重复启动直接复用；后台代码更新且没有任务运行时才更新服务。8123与18125保留各自原网址，由同一个后台处理任务，避免两个进程互相误判任务中断。遇到无法识别的旧服务时，按提示关闭对应启动窗口后重开，不会自动结束未知进程或清空项目。网页开始执行前也会核对后台能力，避免新版页面连到旧后台却仍显示来源已接通。

首次访问需要注册并登录：注册页的测试码定义在 `js/auth-config.js`。这是贡献版的**本地演示级账号门禁**，数据与登录状态仅存浏览器，不是服务器身份认证，也不应作为公网安全机制。

若浏览器显示 `ERR_CONNECTION_REFUSED`，先运行上述启动器，再刷新原网址；本地服务不会随电脑开机自动启动。浏览器研究记录与服务器 `.workbench/` 文件分别保存在本机，克隆仓库不会带入账号、数据库登录状态或任务原始材料。

## 侧栏与保留入口

- **任务**：点击展开，切换当前任务、新建任务、备份或恢复；主工作区不再单独显示任务工具栏。
- **研究空间（工作台）**：点击展开或收起七个固定入口：下载数据、数据清洗、文献挖掘、模型调整与计算、绘图、结果核查与定位、人工审核。首次进入时创建对应模块，不自动执行；绘图等后续模块仍需先确定计算方式。参数/活动数据更新仍作为已有计算子环节保留。
- **工作记录**：保留搜索与返回模块功能，但不显示侧栏按钮。需要时在当前网址添加 `?view=records`，例如 [工作记录](http://localhost:8123/?view=records)；不同端口请保留原端口。也可在浏览器开发者控制台调用 `WorkspaceUI.switchView('records')`，点“返回工作台”即可退出。展示的是当前任务记录，不会删除或重新创建任务。
- **旧九步流程**：仅兼容需要时使用，在当前网址添加 `?flow=1` 可显示原导航和初始化入口；可参阅[九步流程说明](docs/quickstart-research-flow.md)。默认界面不显示此入口，不自动转换已有任务。

## 合并后的能力

- 左侧固定模块与独立研究任务；每个模块保留对话、确认规则和上传文件会话。
- 默认进入「AI 对话」；左侧「添加 API」支持 DeepSeek/OpenAI，也可连接本机 Codex CLI。设置按钮支持**多组模型配置**（一个接口地址 + 一个 Key 为一组，组内维护模型列表，模型名左侧 ▼ 可展开切换、保存时当前模型自动入列；旧版单套配置首次读取自动迁移）与**测试连通**（用表单当前值实调一次本机代理，直接验证地址/Key/模型是否可用），并可补充系统提示词。
- 数据清洗、直接计算、修改计算与结果核查使用本机 Codex；生成环节文档、代码及受限执行是贡献版新增的能力，需要人工审核和确认。执行代码仍有本机风险，运行前必须检查生成内容。
- 工作记录可搜索；浏览器记录可导出/恢复 JSON 备份。备份**不含 API Key、登录状态或服务端 `.workbench/` 上传与输出文件**；迁移整项研究时须另存这些文件。
- 贡献版原有的浏览器多项目记录会在首次打开时一次性转为独立任务；原存储键仍保留。其“写作—投稿”旧流程只作为历史记录展示，不会替换当前固定数据模块。
- 数据下载支持按确认规则获取公开文件，保存原始文件与下载记录，人工确认后自动交给清洗模块；需要登录、网页检索或复杂筛选的来源仍需明确获取方式。
- 原项目的 SOC 文献数据库流水线、流程图和交接文档均保留；通用文献获取不自动套用 SOC 的科学规则或固定表结构。
- 文献模块使用一个「文献任务」启动区域，按六阶段推进候选检索、跨来源去重、全文获取、参数提取、校验和 CSV/Excel 导出；支持原六个来源及新增 PMC、OpenAlex、Europe PMC、Semantic Scholar。按研究需要选择来源，公开 API 通常无需登录；浏览器来源需要登录、验证码或机构访问权限时等待研究者在官方页面处理，再继续原任务。PubMed 接口失败转官方网页时仍保留验证入口。文献旧批次可在折叠记录中继续、补传和交接；下载模块获取公开数据文件，原有文献批次只读保留。

## 下载到清洗

### 文献数据获取：在文献挖掘环节执行

在文献挖掘模块讨论、确认检索与提取要求，再使用「文献任务」核对设置并启动。下载数据模块只用于数据文件下载；旧版混入的文献批次保留为折叠记录，不会被新下载任务续跑。原文献方案执行器的既有批次仍保留下列交付和续跑能力。文献模块中以前已建立的这类批次，可在「已有批次记录」中继续；新任务使用下节的「文献任务」。该方案获取流程首批检索最多 20 条候选、处理最多 3 篇；支持 Europe PMC、Crossref 与 Google Scholar，获取开放全文 XML/PDF 或读取研究者上传的全文与补充表格。模型负责方案解析、筛选及带出处提取，服务器负责检索、获取、解析、证据校验和进度保存；不会执行材料中的指令。方案明确指定 Google Scholar 时使用该来源；既有未指定来源的方案仍默认 Europe PMC/Crossref，不暗中替换来源。发表年份筛选与实验年份分开处理。

遇到规则不明确、缺少全文、单位或数值证据问题时，执行面板显示「需要与你讨论」。可以在对话中讨论，确定后在面板提交答复并继续；获取阶段可上传材料并关联论文，或明确跳过某篇。刷新可恢复状态，服务重启可续跑当前步骤；停止保留已有成果。方案内容改变后须重新审核并开始新批次。

成果包括 literature-list.csv、search-records.json、screening-records.json、原始材料、material-manifest.json、extracted-data.csv、extraction-records.json 和 review-report.md。提取 CSV 保存原值、单位、条件、论文、材料文件、页码/表格位置及逐字证据；缺失留空，数值无证据则不交付为有效值。每次重新提取保留版本文件；最新文件用于核查和交接。核查通过后点击「将提取表交给清洗」，只复制数据表，不把 PDF/XML 混入清洗输入。

- 候选检索支持 **Google Scholar、知网、万方、Web of Science、Scopus、PubMed、PMC、OpenAlex、Europe PMC、Semantic Scholar**。公开 API 检索通常无需验证码；知网 / 万方 / WoS / Scopus 在需要人工登录或机构权限时暂停，由研究者在官方页面处理。`sourceQueries` 可为每个来源单独指定检索式；测试运行每来源最多 10 条；正式检索可按每来源 50/100 条或取到可访问末页，浏览器来源、PubMed 与四个开放 API 来源均支持翻页（到接口硬上限会如实暂停，不把来源上限当作末页）。①调研面板也可选择测试/正式规模；正式检索遇到登录/验证会保留已下载候选，并提示到文献挖掘面板继续。全文优先开放 PDF，其次 PMC JATS/HTML；正文缺核心章节标 `partial`（不进入提取），补充材料按清单下载并单独标完整/部分/未核查。地域与研究类型只有写入检索式才会影响检索阶段的搜索；语言、纳排规则和目标字段随配置保存，供后续阶段使用。
- 候选清单保留标题、结果链接、全文链接（如有）、页面片段、来源、检索时间与待复核状态；批内按标题去重，跨批/跨来源重复由去重阶段归并。片段不是已核实的摘要或全文，候选不是已纳入文献。结果必须记录检索 URL 与实际应用的筛选条件；失败或验证码要给出真实状态。
- 自动化只做“明确重复/无法获取”的判断：去重仅自动排除明确重复；全文获取不重试无法合法获取项；不自动判“不相关”。参数字段以研究者确认记录为准（`confirmations.json`），不把 AI 建议当已确认规则。提取行必须带出处，阻断/待审核行按规则分流，被排除文献仍保留筛选记录。
- 本阶段仍**不**做：PDF 上传后自动解析题录、图表像素读数（人工转录可补录）、代理自动发现、OCR/图像数值估读。无合法全文的文献标为待补充。
首期不自动登录文献来源、不绕过访问控制、不做 OCR 或图像数值估读，不宣称全量检索。PDF/Excel 读取使用已有 Python 与 pypdf/pdfplumber/PyMuPDF/openpyxl；缺少依赖时显示问题，配置 `WORKBENCH_PYTHON` 可指定现有解释器。模型限流时保留等待状态，可稍后继续或在设置选择可用模型。

接口依据：[Europe PMC REST](https://europepmc.org/RestfulWebService)、[Crossref REST](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)。

### 文献检索与提取（六阶段）

文献挖掘模块的「文献任务」是新任务启动区域。可从已确认的对话整理规则，也可手动填写；展开「本次检索设置（点击查看或修改）」核对检索式、来源、发表年份和运行模式后，点击「确认配置并检索」才会执行。**测试运行**每来源最多取 10 条；**正式检索**自动翻页到各来源可访问的末页，不设置候选数量上限。每页保存成果；登录、验证、网络或来源访问限制会暂停，处理后点「检查并继续」续跑原任务。来源访问限制会说明原因，不会标记为全部检索完成。旧任务仍按启动时冻结的配置续跑。六来源可单选或多选，各来源独立检索式留空时沿用默认检索式。知网和万方可填中文检索词；Scopus 在 Documents 的 Title Abstract Keywords 字段提交布尔检索式；PubMed 支持 `[Title/Abstract]` 等官方字段语法。「仅检索候选」在本轮测试/正式检索结束后停止；使用「继续下一阶段」或「本次做到哪一步」推进去重、全文获取、参数提取、校验和导出。提取前必须确认参数字段含义与单位。操作说明在右上角「使用说明」弹窗；已有阶段任务在「历史任务」中找回，旧方案获取流程的既有批次另收在「已有批次记录」中。

已有文献任务可点击「设置提取字段」，在弹窗中与 AI 讨论表头、含义和单位，再点击「按讨论填入表格」，把整理结果直接填入下方可编辑表格。组合表头拆为独立变量，最多 200 个字段；未决事项单独保留，可恢复应用前的草稿。草稿与讨论按任务保存在当前浏览器；「保存草稿并关闭」不启动执行。进入字段确认关口后，核对表格并点击「核对表格并开始提取」，把当前表格交给原任务，仅推进到提取；已有候选和材料继续复用，无需重新检索。外部阶段下拉框不会改变这个明确的提取操作。

正文优先取得 PDF，已核验网页正文可作为后备；补充材料保留原格式，逐篇登记保存、读取和缺失情况，入口为「每篇材料清单」。Excel、Word、PDF、CSV、ZIP 等材料的读取结果会进入提取输入；无法读取、只有摘要或材料不齐必须保留标记。已核验材料按强身份和 SHA 复用，避免重复下载。获取失败时可明确选择跳过并继续，保留原因和已取得的材料；登录、验证、限流页面不会被当作正常全文。

PubMed 默认使用 NCBI 官方 E-utilities 查询公开题录与摘要，通常无需登录，保留 PMID、DOI 和公开全文链接；接口失败时可在同一 PubMed 来源转为官方网页，记录实际获取方式，不静默更换数据库。摘要用于候选筛选，不能当成全文数据证据。

数据库检索使用平台专用的持久浏览器，已在该窗口完成的登录可供后续任务复用；普通 Edge/Chrome 的登录不会自动共享。可访问的结果页直接检索，需要登录、验证码或机构权限时暂停，每轮等待会自动请求打开原任务的官方窗口一次；自动打开失败可点「打开登录/检索页面」重试。无法识别的页面会保留人工核对入口，不冒充零命中或已登录。在官方页面完成操作后，回工作台点「检查并继续」；机构登录在另一标签完成时，平台会重新访问已确认的检索入口核验会话。原任务等待页、已完成来源和运行边界保留，不另建任务。账号密码仅在官方网页输入；平台接口不接收密码、Cookie 或 SSO 令牌。个人登录不等于具有数据库或全文访问权限，仍须有效机构订阅、授权网络或其他合法权限。

来源和检索式随 `run_config.json` 冻结，修改后须确认新配置并发起新任务；不会将改后的要求混入旧结果。历史任务可重新载入原配置并续跑。连接器使用真实页面结果，登录页或未知页面不当作“零命中”；公开模板及人工登录恢复路径由自动化测试覆盖，具体账户和机构权限下的真实检索仍需研究者首次试跑验证。

完整流程也复用这个 Scholar 连接器，把候选继续送入筛选、获取材料与数据提取。搜索片段只用于筛选，不能作为数值证据。Scholar 遇到验证码时暂停，请在检索浏览器中手动完成验证后点击继续；不会自动解验证码。配置不变时读取已验证结果页，已完成查询复用冻结结果。

Scholar 首次运行需要 Python 3.10+，自动准备项目 `.venv/`、`requirements-literature.txt` 依赖和 Chromium，可能需要几分钟；安装或网络失败会明确显示。使用已有代理环境变量，Windows 也支持已启用的系统 HTTP 代理。该最小环境用于检索，不等于自动安装全部计算或 PDF/Excel 解析依赖。

### 数据文件下载：审核方案后执行

1. 在下载模块与 AI 讨论来源、年份、地区、商品/变量和验收要求，核对并审核下载方案。
2. 点击「按方案开始下载」。已接入的 FAOSTAT TM 详细贸易矩阵路径可从官方目录定位整包，按已确认条件交付筛选文件；保留官方原包、来源、SHA 和筛选记录。通用公开文件方案也使用后台下载任务，单个文件最多 2GiB。FBSH 清洗练习案例另见 examples，不代表该数据集的自动定位也已接通。
3. 在「文件与结果」查看进度和下载记录。中断保留已完成文件和可用断点，服务重启后由用户手动继续；来源不支持续传时会重新下载。同版本、完整且校验通过的原包可以复用。
4. 核对文件符合来源、年份、范围及版本要求后，点击「确认文件并进入清洗」。平台复制原始文件到清洗模块，后续讨论并确认清洗规则；清洗结果按主要结果、检查报告、待处理问题分组，支持下载所选运行的结果 ZIP。

兼容的手动地址弹窗和手动上传仍限每文件 20MB，最多 5 个地址，格式为 `地址 | 文件名`；它不替代上述后台大文件任务。网页地址不等于实际文件地址，下载成功也不等于人工验收通过。其他数据库的自动定位、登录和分页能力须逐一接入，不能据此认为任意来源都可自动下载。

## 方案继续讨论与修订

已有方案卡片提供“AI 总结并修改方案”。先在模块对话中说明修改要求，发送后点击按钮，AI 会以完整当前方案为基线，结合最近讨论生成完整修订草稿；未变更规则保留，未确认项仍待确认。草稿不自动审核或执行，核对后重新审核，再使用该模块的执行入口。

修改前的版本保存在卡片下方“历史方案”，可查看、恢复为草稿；恢复也需重新审核。生成失败或期间方案发生变化时不覆盖原文。历史方案随浏览器“备份”导出；仅保存文字与审核信息，服务端原始文件和成果仍需单独保存。

## 配置与检查

### 绘图

绘图模块支持上传 CSV/TSV/Excel/JSON/TXT，选择本次数据并与 AI 讨论，打开顶部绘图方案弹窗审核后生成。首次读取绘图数据或生成时自动准备项目 `.venv` 内的 `requirements-plotting.txt`，需要 Python 与可访问的公开包源；已有绘图依赖时直接复用。实际绘图通过本机 Codex 执行，使用当前模块所选模型。

预览区按版本展示实际生成的 PNG/JPEG/WebP；可下载图片、SVG/PDF、绘图代码、绘图数据与运行说明。填写某版修改意见后先讨论，再修订和审核方案生成新版本，旧文件保留；失败、停止和重启中断的版本也显示真实状态，不计为完成。首次使用或升级后须运行工作台启动器以加载新版后端。

本机 Codex 需要安装 CLI；在左下角“设置 → 模型”选择本机 Codex 并点击登录按钮，完成官方浏览器登录即可。已有本机登录时直接复用。macOS 也可复用桌面应用内置 CLI；`CODEX_BIN` 可指定路径。模型与后端按当前模块保存；生成环节文档、代码和 AI 定位也使用所选后端。无需填写 API Key。API 对话仍可在页面配置密钥，或使用 `.env`。

Python 依赖统一维护在 [`requirements.txt`](requirements.txt)，可用左侧「编辑依赖」打开；通用表格处理包括 `pandas>=2.0,<4`。文献检索、绘图、清洗 Excel 的按需安装清单分别为 `requirements-literature.txt`、`requirements-plotting.txt`、`requirements-cleaning.txt`；模块安装不等于安装总清单中的全部依赖。统一使用 Python 原生 venv 创建的项目 `.venv/`，不使用 conda；`.env` 仅用于服务配置。现有环境单独补装 pandas：

```bash
.venv/bin/python -m pip install 'pandas>=2.0,<4'
```

## 调试

出问题时不用猜、不用截图来回传——服务端的请求记录、异常与前端错误都收在内存缓冲里，
用一条命令拿到人读的中文诊断摘要：

```bash
node tools/debug-report.js              # 服务状态、模型、失败请求、慢请求、错误明细
node tools/debug-report.js --port 8124 # 指定端口
node tools/debug-report.js --json       # 原始 JSON
```

也可以开 <http://localhost:8123/debug.html> 用眼睛看（侧栏入口默认隐藏，地址栏加 `?debug=1` 才出现）。
日志只在内存、进程重启即清、不含请求体、API Key 一律脱敏。用途与排查手册见 `docs/debug-tool.md`。

更多说明见 `docs/user-guide.md`、`docs/debug-tool.md`、`docs/workflow-drafts.md`、`docs/开发交接.md`。早期说明存于 `docs/README-历史版本.md`；其中的静态演示限制已过时。
