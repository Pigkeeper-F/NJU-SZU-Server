# 流程智能体 · 演示前端

当前首页已升级为「研序 · 研究工作台」：提供研究空间、工作记录汇总、项目命名、备忘和 Markdown 导出。新增界面层位于 `css/workspace.css` 与 `js/workspace.js`，沿用原有模块及消息存储。默认的「记录模式」只保存本地记录；手动切换「AI 对话」后才使用下方说明的已配置服务。此次界面不预设具体科研流程。

项目名称和备忘使用独立的本地存储键 `research_workspace_meta_v1`；原有模块及消息仍使用 `fa_state_v1`。下文保留原基础组件及接口说明，首页外观和默认输入模式以当前界面为准。

一句话：**「流程智能体」演示前端 —— 左侧栏「流程」选项卡 + 顶部强依赖模块选项卡（A → B → C）+ 每个模块独立的会话空间 + 底部输入框。**

零依赖（无框架 / 无打包 / 无 CDN / 无 ES module），双击 `index.html` 即可运行。

## 快速开始

### 方式一：双击直开（推荐）

直接双击 `index.html`，浏览器以 `file://` 打开即可查看与编辑本地消息。AI 回复需要按下方方式启动本地服务。

### 方式二：本地静态服务器（可选）

```bash
cp .env.example .env
# 编辑 .env，填写 AI_API_KEY（不要提交该文件）
npm start
```

然后浏览器访问 <http://localhost:8123/>。服务端会代理 `POST /api/ai/chat`，密钥不会暴露给浏览器。

> 两种方式行为一致（同源 localStorage）；只有跨 `file://` 与 `http://` 切换时数据不共享。

## 功能说明

| 区域 | 能力 |
|---|---|
| 左侧栏 | ①「流程」选项卡（逻辑支持多选项卡，当前只有 1 个）；② 折叠按钮 `☰` 收起为 44px 细条，再点展开；③ 右侧 6px 手柄拖拽调宽（实时跟手，松手才落盘，宽度夹取 180~520px）；④ 双击手柄也可折叠/展开；⑤ 底部小字提示 |
| 顶部模块条 | ① `＋` 追加模块（自动命名 模块1 / 模块2 / 模块3…）；② 新模块的依赖 = 当前链尾 ⇒ 天然强依赖链 `模块1 → 模块2 → 模块3`；③ 卡片显示模块名 + 依赖徽标（首模块 `起点`，其余 `← 上游模块名`）；④ 双击卡片标题可重命名；⑤ 卡内 `×` 删除，**只有链尾可删**，非链尾的 `×` 变灰并给出系统提示；⑥ 右侧显示整条依赖链概览 |
| 模块空间 | 每个模块一份独立消息历史，互不串台；有模块空间头部（模块名 / 依赖来源 / 消息条数）；消息气泡按角色区分（用户右对齐、助手左对齐、系统居中虚线）；空状态引导 |
| 底部输入框 | Enter 发送、Shift+Enter 换行；输入法（中文/日文等）候选未上屏时按 Enter 不会误发；高度自适应，最多 180px 后内部滚动；无模块 / 未选中模块时自动禁用并改占位文案 |

## 键盘与鼠标操作

| 操作 | 方式 |
|---|---|
| 发送消息 | `Enter` 或点「发送」 |
| 换行 | `Shift + Enter` |
| 新建模块 | 点顶部 `＋` |
| 切换模块 | 点模块卡（点 `×` 不会同时切换） |

| 调整侧栏宽度 | 拖拽侧栏右侧 6px 手柄（180~520px） |

## 数据存储

- 存储位置：浏览器 **localStorage**，键名 **`fa_state_v1`**（`Store.LIMITS.STORAGE_KEY`）。
- 存的内容：整份 state —— `sidebar`（折叠态 / 宽度）、`tabs` / `activeTabId`、`modules`（含每个模块的消息）、`activeModuleId`。
- 每次状态变更都会**先落盘再广播**；刷新页面后模块链、消息、侧栏宽度与折叠态全部恢复。
- **换浏览器、换设备、清缓存 / 清站点数据、或用无痕窗口打开，数据都会丢失**（localStorage 按 origin 隔离）。
- 清除数据（二选一）：
  ```js
  // ① 控制台复位为默认状态（推荐）
  Store.resetAll();
  // ② 直接删键后刷新页面
  localStorage.removeItem('fa_state_v1');
  ```
- 隐私模式 / 配额写满时：写盘失败会被静默忽略，页面降级为**纯内存**，功能仍可用（刷新即丢）。

## AI 接口配置

默认按 OpenAI Responses API 调用。复制 `.env.example` 为 `.env` 后填写 `AI_API_KEY`；可用 `AI_MODEL` 改模型。若使用 OpenAI 兼容的 Chat Completions 服务，设置 `AI_API_BASE_URL`、`AI_MODEL`，并将 `AI_API_PROTOCOL` 改为 `chat-completions`。前端只调用同源 `/api/ai/chat`，不会拿到密钥。

> 📄 **想接入模型让它直接编辑模块内容？** 调研结论、CORS 与密钥安全、工具调用（tool_calls）设计、
> 契约变更提案与分阶段实施计划，见 [`docs/llm-integration-research.md`](docs/llm-integration-research.md)
> （**目前仅调研文档，代码未实施**；`.gitignore` 已预先屏蔽本地密钥文件）。

## 已知限制（演示版）

- 消息只存在本地，**没有模型服务**（见上）。
- 模块删除是一次性的，**没有撤销**；删掉链尾模块会连带丢掉它的消息。
- 依赖链只支持「顺序追加」，不支持插入 / 重排 / 修改依赖；删除只允许链尾（数据层同样会拒绝）。
- 模块空间与顶部卡片在每次状态变更时整体重建；消息很多（数百条）时高频操作（如拖拽调宽）会有可感知开销。
- 拖拽基于 Pointer Events，未在真实触屏设备上实测；无 Pointer Events 的旧浏览器无鼠标降级方案。
