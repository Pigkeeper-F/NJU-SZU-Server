## 文件对应关系

- [run-config.snapshot.json](run-config.snapshot.json)：原任务的冻结配置，保留当时全部文字。前两条纳入规则写有“原测试已取消”“从现有50条候选开始”等历史操作描述，与本快照实际 10 条候选不同，不应用它们判断当前进度或新任务。
- [reuse-config.json](reuse-config.json)：供接手者核对的新任务配置草稿。移除上述两条历史操作描述，带入原任务确认的 75 个字段，其余科学规则保留；这份草稿不代表新一轮研究已经确认或获得运行授权。
- [field-definitions.json](field-definitions.json)：字段名称、含义、单位、类型及原任务确认时间。新任务仍需人工检查单位、研究层级、比较关系与适用范围。
- [candidates.json](candidates.json)：10 条候选的公开题录与永久链接，移除了摘要片段。
- [literature.csv](literature.csv)：10 行文献导出及原筛选/审核状态。
- [parameters.csv](parameters.csv)：259 行参数导出，保留原值、单位、条件、位置和自动校验状态。入库版移除了 `evidence_quote` 列。
- [extraction/](extraction/)：3 篇逐篇提取 JSON，已移除 `evidence.quote`；与参数表同源。
- [material-status.json](material-status.json)：原任务的逐篇材料状态与文件指纹。`download_status` 表示原电脑当时的状态；`local_files_included: false` 表示这些材料没有打入本案例。
- [validation.json](validation.json)、[validation.md](validation.md)、[extraction-check.json](extraction-check.json)、[export-report.md](export-report.md)：保留原检查结论及待审问题。
- [verify_case.py](verify_case.py)：仅离线核对本案例的文件、字段、行数和引用关系，不检索、不下载、不调用模型。

正文、补材、原始 Excel、浏览器登录状态、API Key、本机路径和模型输入包没有复制进来。需要原件时，请通过文献表的 DOI/官方入口，在具有适当权限的环境另行取得；取不到的材料继续保留缺失状态。

## 先看哪些问题

1. **材料没有齐全。** 三份可用正文是网页文本，不能宣称取得三份 PDF，也不能把未发现附件视为“无附件”。
2. **科学筛选还需要人工完成。** `PMID-002` 的提取结果已明确说明是综述中的二次报告（8 行），不能直接作为独立原始实验数据纳入。其他记录同样需要按研究类型、温度对比和目标指标回原文审核。
3. **8 条单位问题没有处理。** `PMID-007-R144` 至 `PMID-007-R151` 的 `variation_value` 缺少单位。必须先核对原表及字段含义，不能为消除提示自行填单位。
4. **259 行不是 259 个独立实验。** 它们包括文献元信息、条件和报告值；研究/实验/处理组关系、重复报告、共享对照仍须核对。
5. **自动校验只验证当前契约。** 原文引用在此分发版中被移除；核查证据需回官方原件，本快照不能独立证明全部数值正确。

## 如何继续使用

### 检查已有输出（不运行平台任务）

在本目录执行：

```powershell
python verify_case.py
```

或者从仓库根目录执行：

```powershell
python examples/broiler-heat-stress-pilot/verify_case.py
```

Python 3.10+ 即可，无第三方依赖。成功会显示 `BROILER_CASE_CHECK_PASS`。CSV 使用 UTF-8 BOM，方便 Excel 识别中文；字段含义优先查 `field-definitions.json`。

### 在原电脑上接着做

本地 `.workbench/` 仍保留原任务、原材料和完整证据。启动工作台后，从“文献挖掘 → 历史任务”找到原任务编号，先核对材料清单、筛选状态和待审问题。不要为了查看这个案例重新检索，也不要把此处脱除引用的副本覆盖原任务。

### 在新电脑复现小样本

1. 按仓库 README 启动本地工作台，新建独立案例任务；先在自己的官方页面完成所需登录。
2. 将 `reuse-config.json` 作为讨论资料提供给文献模块，核对主题、规则、来源、字段和本次运行边界。它是配置参考文件，**不是浏览器“恢复”备份，也不是服务器历史任务导入文件**。
3. 首轮选择 PubMed、测试模式，先仅检索 10 条候选。实时检索结果会随数据库更新，不能保证与历史快照相同。
4. 确认筛选及材料获取规则，取得允许访问的正文与补材。需要登录、权限、验证或材料不可得时保留真实状态。
5. 在“设置提取字段”中讨论并填表，核对后才开始提取；首批提取需人工逐项回原件核查，随后再校验、导出。

本案例文件本身不会创建或恢复任务，也不会自动连接数据库、下载材料、确认科学规则或执行模型。
