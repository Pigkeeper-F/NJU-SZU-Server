# 模块工作流初始版本索引

各模块统一按“定义、输入、执行、交付、检查、异常、需对齐内容”讨论。以下是业务草稿，待对齐问题尚未作为执行策略实现。

| 模块 | 工作流文档 | 主要输出 |
|---|---|---|
| 下载数据 | [草稿](download-data-workflow-draft.md) | 原始数据包、来源清单与下载摘要 |
| 数据清洗 | [草稿](clean-data-workflow-draft.md) | 清洗数据、规则、质量与变更报告 |
| 计算（直接计算/修改计算） | [工作流](calculation-workflow-draft.md) | 原代码运行或按确认规则修改后运行；结果、代码与日志 |

## 跨模块需对齐内容

1. 界面的固定模块排列与真实执行依赖如何对应？业务图中活动数据与参数流水线汇入计算，审核还可能发生在多个节点；排列不应直接当成所有任务的执行时序。
2. 是否支持参数更新与活动数据更新同时参与一次计算，以及失败后局部回流？
3. 各模块共同采用什么成果版本、运行状态和交接标识，如何记录下游使用的上游版本？
4. 哪些决定由用户确认，哪些已有规则允许自动复用；规则变化触发哪些下游复验？
5. 原始文件、中间成果、证据、日志和最终结果的保存位置与历史保留方式是什么？
6. “完成”“部分完成”“待确认”“待审核”“失败”等状态如何统一，哪些状态允许下游继续？
