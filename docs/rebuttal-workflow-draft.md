# 回复审稿意见、修改与复核工作流（讨论草稿 v0.1）

> 九步研究流程 · 环节⑧（第二阶段第二步）。对应业务流程表「回复审稿意见、修改与复核：
> 针对意见修改研究和论文，检查回复与修改是否对应」。
> 上游是环节⑦投出的稿件版本；下游是环节⑨接收后的校稿核验。

## 定义

把审稿意见逐条落到可执行的修改上：区分意见性质、决定接受或申辩、必要时补做实验，
修改稿件与研究，写出逐点回复，并检查每条回复与实际修改一一对应、修改后全文仍然自洽。

## 输入

- 必需：审稿意见原文（编辑信 + 各审稿人意见，保留编号）；被审版本稿件及其上游产物。
- 可选：编辑给出的修改期限、期刊是否允许 resubmission、已有的补充实验数据、
  上一轮回复与修改记录。
- 意见原文必须完整保留：不擅自合并、改写或省略审稿人原话。
- 无法判断意图的意见先列为待澄清，不擅自替审稿人定调。

## 执行

1. 拆解意见：逐条编号，保留原话，标注所属审稿人与类别。
2. 分类：接受并直接修改 / 接受但需补实验或补材料 / 部分接受并说明 / 有异议并给出依据 /
   超出本次范围但已回应。分类理由写清。
3. 影响评估：每条意见对应到稿件的具体位置（章节 / 段落 / 图 / 表 / 公式），
   标注修改类型（文字 / 数据 / 图表 / 分析 / 补充材料 / 无需改动）。
4. 制定修改计划：按代价与依赖排序，标出必须补做的实验及其数据需求。
5. 执行修改：补做实验并落盘产物 → 更新图表与数据 → 修改正文 → 更新参考文献与声明。
6. 撰写逐点回复：每条按「审稿人原话摘要 → 我们的回应 → 具体改动（位置）→ 依据」组织；
   有异议的给出文献或数据支撑。
7. 修改稿全文一致性复核：数字、编号、引用、图表、术语、新增内容与摘要结论是否同步。
8. 输出复核报告：逐条意见 → 回复条目 → 稿件改动位置的三向对照。
9. 交人工审阅并定稿，登记本轮版本。

## 交付

- 意见拆解表：编号、原话、类别、理由、影响位置、修改类型、状态。
- 修改计划：补做实验清单与依赖顺序。
- 逐点回复信：按审稿人分节，可直接提交。
- 修改稿（含补充材料与新增图表）。
- 修改对照表：改前 → 改后（位置 + 摘要）。
- 复核报告：三向对照表 + 修改后全文一致性检查结论。

## 检查

- 每条审稿意见都有对应回复条目，无遗漏、无合并。
- 每条回复都指向稿件中的具体改动位置（或明确说明不改并给出理由）。
- 有异议的意见给出了文献或数据支撑，而非主观断言。
- 补做的实验有产物、有记录；正文未把未完成的实验写成已完成。
- 修改后全文数字与图表、结果文件一致；摘要与结论与正文同步。
- 新增或删除的图表编号连续、引用双向齐全。

## 异常

- 意见相互冲突：并列呈现，说明各自依据与取舍，请人工裁定。
- 意见超出可完成范围（需重新采集数据、需额外设备）：如实说明代价与时间，给出折中方案。
- 无法复现审稿人关心的问题：先复现并定位是稿件表述问题还是结果问题，再决定回应方式。
- 修改引发新的不一致：以复核报告为准，回到对应环节修，不在回复信里掩盖。
- 修改期限过紧：优先处理影响结论与可复现性的意见，其余标注延期并说明。

## 需对齐内容

1. 审稿意见的来源形式（投稿系统导出 / PDF 标注 / 手工录入），决定解析方式。
2. 补做实验是否允许在本环节直接调用执行内核，还是回退到上游环节重跑。
3. 逐点回复的模板与语气（是否需要英文正式语体、有无字数限制）。
4. 是否需要生成修改稿与原版的 diff 文件。
5. 拒稿或 major revision 之外的小修，是否走同一套流程。

## 与环节⑨的衔接

本环节定稿的稿件版本与逐点回复，是环节⑨校稿核验的对照基线；
进入⑨时需携带「终稿版本标识 + 本轮全部修改记录」。
