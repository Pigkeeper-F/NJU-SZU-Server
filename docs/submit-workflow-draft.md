# 投稿前核验与投稿工作流（讨论草稿 v0.1）

> 九步研究流程 · 环节⑦（第二阶段第一步）。对应业务流程表「投稿前核验与投稿：
> 核查整个研究过程及论文材料，再准备投稿稿」。
> 上游是环节⑥的文章终稿与其全部上游产物；下游是环节⑧回复审稿意见。

## 定义

在稿件投出去之前，把整个研究过程与论文材料从头核一遍，确认内部一致、对外合规，
并产出完整可投的投稿材料包。核验以证据为准，逐项给出结论与依据，不做无依据的放行。

## 输入

- 必需：终稿（含图表、参考文献）；全部上游产物（问题陈述、方法与运行记录、
  结果数据、图表源文件、代码）；目标期刊的投稿要求。
- 可选：作者与单位信息、基金与资助号、伦理审批号与知情同意声明、利益冲突声明、
  数据与代码可用性声明、推荐与回避审稿人、投稿信模板。
- 稿件与上游产物版本不一致时，以「谁是最新版」为先决问题，未对齐前不进入核验。
- 缺少作者 / 基金 / 伦理等元数据时，生成占位并标为待填，不臆造。

## 执行

1. 确认版本基线：定下本次投稿对应的稿件版本与上游产物版本，记录其标识。
2. 四方一致性核验：结果数据 ↔ 运行代码 ↔ 图表 ↔ 稿件正文，逐项核对关键数字。
3. 研究过程核验：问题是否被回答、方法是否如稿件所述、结论是否越界、局限是否如实交代。
4. 格式核验：目标期刊的结构、篇幅、图表格式、参考文献样式、匿名要求（双盲时去标识）。
5. 元数据核验：作者顺序与单位、通讯作者、基金与资助号、伦理与知情同意、
   利益冲突、数据与代码可用性、贡献者声明。
6. 投稿要件核验：摘要、关键词、Highlights / Graphical Abstract、封面信、
   补充材料、投稿系统必填项。
7. 出自查清单：每项标 通过 / 不通过 / 不适用，附证据位置；不通过项写明修法建议。
8. 修复后复验：对修改过的项再次核验并留痕。
9. 汇总投稿材料包，登记投稿信息（期刊、稿件号、投稿日期、版本）。

## 交付

- 投稿前自查清单：逐项结论 + 证据位置 + 修法建议。
- 一致性问题清单：稿件与产物不一致的地方，含定位与影响判断。
- 投稿材料包：终稿（按期刊要求形态）、图表、补充材料、封面信、摘要与关键词、
  Highlights / Graphical Abstract（若要求）、声明页。
- 封面信草稿：研究价值、方法要点、主要发现、与该刊读者相关性的说明。
- 投稿信息登记：目标期刊、版本、投稿日期与后续编号占位。

## 检查

- 关键数字在结果文件、图表与正文三处完全一致。
- 稿件所述方法与实际运行记录相符；未把计划中的做法写成已完成的。
- 结论未超出证据范围；局限与失败情形已如实写明。
- 目标期刊的硬性要求逐条核对（结构、篇幅、匿名、图表格式、引用样式）。
- 作者 / 基金 / 伦理 / 冲突 / 数据声明齐备且与实际情况一致，无占位残留。
- 封面信与稿件内容一致，未夸大贡献。
- 提交前稿件版本与投稿材料包为同一版本。

## 异常

- 数据与正文对不上：以可复现的结果文件为准，回退到对应环节重新核对并记录。
- 目标期刊要求与现有材料冲突：列出冲突，给出改写、补充或改投的方案，交人工决定。
- 伦理或基金信息缺失：标为阻塞项并明确需要谁提供，不代填。
- 双盲要求：去标识后再出材料包，并保留去标识记录。
- 篇幅超限：按写作环节的压缩原则处理，说明删减了什么。

## 需对齐内容

1. 投稿材料包的形态：直接生成可上传的最终文件，还是生成清单由人按系统逐项填。
2. 封面信是否需要按期刊分模板。
3. 期刊投稿系统是否有 API 可对接（决定「完成投稿」是自动还是人工点提交）。
4. 自查清单里哪些项允许 AI 直接判通过，哪些必须人工签核。
5. 伦理与数据声明的固定模板从哪来。
