# 数据清洗：检查、执行与复现

当前实现：通用读取与核验程序 + 按已确认规则生成的项目脚本。支持CSV、TSV、XLSX、XLS；不预设商品、国家、年份或科学处理方法。

## 网页使用

1. 在数据清洗模块上传原始文件，或接收下载模块交接的文件。
2. 展开“数据检查与处理范围”，选择本次文件。CSV/TSV可选择编码；Excel先检查列出工作表，再选择要处理的表。未选择单独工作表时表示全部工作表。
3. 点击“检查所选数据”，查看固定程序的行列、空值、重复、数值分布及问题清单。用AI讨论时，所选输入也会先经过该固定检查。
4. 讨论目标、范围、步骤和特殊说明，在“执行规则”中核对并确认；点击执行。AI候选规则不会自动生效。
5. 平台依次检查输入、生成脚本、冻结任务、执行及独立核验。关键口径缺失、结构歧义或核验失败会明确显示，不自动用新假设继续。
6. 在“清洗结果”中查看所选版本、检查报告和逐行来源；可下载结果包，或下载含代码与依赖记录的复现包。原始输入默认不加入复现包，可勾选加入。
7. “按原脚本另建版本重跑”使用原输入指纹、规则和脚本，另存结果并比较数据文件SHA-256；不会重新生成清洗代码。原运行保留。

规则或处理范围改变时重新确认并执行新任务；原脚本重跑用于复现原任务，不会应用当前规则草稿。

## 能力与判定

- Excel读取保存值，不重算公式。XLSX公式缺少缓存、存在错误值、合并单元格或表头空白/重复时，先处理问题或改选工作表。XLS不能可靠识别公式来源，报告为unknown，不宣称检查过全部公式缓存。
- 输入按完整逻辑记录检查，不默默丢弃空白记录。当前每表最多50万行、500万单元格；超过时明确报告需限定范围，不用抽样结果冒充全量检查。
- 字段以可追溯的文本值交给项目脚本；文本编码的前导零保留，数值变换使用明确规则和精度。Excel数字显示格式不等于原始文本，XLS日期保留序列值并记录日期模式，具体解释需确认。Excel原格式与公式仍留在原始文件，规范数据输出为CSV，并非原工作簿的无损重存。
- 固定核验检查输入/脚本指纹、输出读回一致性、每行来源及所有原记录去向。可按确认规则核验行数、唯一键、非空字段、原字段保留、精确倍数换算及去除一个前缀；每条项目检查引用确认规则原句。其他业务验收列为待判定。
- `passed`表示所登记程序检查通过；`partial`表示另有业务检查待判定；两者都不表示研究者已完成科学验收。失败不发布“全部通过”。
- 网页通过已有Codex沙箱运行冻结脚本，写入本次输出目录。复现包可用Python直接运行，无需模型；直接运行项目代码仍需使用可信的任务包。
- 模型目录必须与实际账号支持一致：目录列出但执行端拒绝的型号会使任务明确失败，不静默切换模型。离线测试通过不代表真实模型联调已通过。
- 当前工作台优先使用目录中的`gpt-6-sol`，推理强度明确为`high`；macOS优先新版桌面包中的`codex-cli/bin/codex`，避免误用PATH中的旧CLI。冻结脚本重跑保留原模型及推理记录。

## 文件与程序入口

| 文件或入口 | 职责 |
| --- | --- |
| `tools/cleaning_core.py` | 固定读取、画像、项目函数调用、序列化及核验；命令为profile/run/verify |
| `tools/cleaning.js` | 任务状态、冻结计划/代码、Codex衔接、重跑及复现包 |
| `tools/cleaning-runtime.js`、`requirements-cleaning.txt` | 复用/创建项目`.venv`，按需准备openpyxl和xlrd；CSV/TSV只需Python标准库 |
| `.workbench/<session>/.cleaning/<id>/` | 持久状态及受保护的冻结包；服务重启将未完成任务标为interrupted，不自动重做 |
| `.workbench/<session>/output/<id>/` | 数据画像、冻结计划副本、CSV结果、逐行来源、程序核验及报告 |
| `/api/codex/cleaning/profile`（POST） | 接收sessionId及inputs（name/encoding/sheets），返回固定检查 |
| `/api/codex/run`（POST） | 清洗执行须携带cleanPlan：confirmed、text、version、inputs |
| `/api/codex/job`、`/api/codex/cancel` | 带session与id，读取持久任务状态/停止；旧普通Codex任务接口兼容 |
| `/api/codex/cleaning/replay`（POST）、`archive`（GET） | 原脚本新版本重跑、下载复现包；inputs=1才包含原件 |

复现包包含`clean.py`、`cleaning_core.py`、`cleaning-plan.json`、`requirements-lock.txt`、运行说明和原结果；勾选时另含`inputs/`。计划保存规则版本、文件/脚本/内核指纹、生成模型与推理配置、Python及Excel依赖版本；核验报告另记本次实际环境及原冻结环境，无法取得的信息记录unknown。执行所需解释器与冻结记录不同不应当作环境相同，重跑数据哈希比较可暴露结果差异。

项目函数接口：`clean(tables, config)`返回结果表、逐输出行的`lineage`和未进入输出的原记录`dispositions`。支持一对多、多对一及明确排除；固定核验核对去向，具体删除/合并理由仍按已确认科研规则判断。

## 开发检查

```bash
# 固定内核离线回归；从项目根目录运行，Python需3.10+。
python -m unittest discover -s tools -p test_cleaning_core.py
# 任务编排、持久状态、冻结脚本重跑与异目录复现，不调用真实模型。
node tools/test-cleaning.js
# 隔离浏览器交互检查；需要已有Playwright及Chromium，模型接口均为测试响应。
python tools/test_cleaning_ui.py
```
