# 文献挖掘工作流：从主题到文献 meta 与研究参数

## 目标与边界

输入一个研究主题及可选范围，产出有来源证据、可追溯、可复核的文献元数据和主题相关研究参数。工作流不绑定 SOC、特定学科或固定字段；每次运行根据主题配置检索源、筛选规则和数据字典。自动化负责发现、整理和初步提取，不替代研究者制定科学判断，也不把低置信度结果伪装成确定数据。

## 输入

必需：

- 研究主题或研究问题。

可选：

- 研究目的、学科/对象、地域与时间范围、目标文献数量。
- 纳入、排除和待复核标准，以及检索数据库/来源范围。
- 目标 meta 字段与参数字段、单位/类别规范、目标输出格式。
- 已有文献清单、参考样本、历史数据或用户提供的文件。

缺失的关键条件应先整理为待确认项；可提供建议默认值，但不能静默把建议当成用户定下的科学规则。每次运行保存最终采用的输入、范围和规则版本。

## 执行

1. **解析主题与方案**：将主题拆成概念、同义词、缩写、对象和可能的参数；形成检索式、来源列表、纳排规则及字段模板。显式区分“硬性纳入/排除”和“需人工判断”。
2. **检索与留痕**：从配置来源发现候选文献，记录来源、检索式、检索时间和可用标识符。来源接入应遵守访问权限、服务条款和合理请求频率。
3. **归并与初筛**：以 DOI、标准化标题等稳定标识去重；逐条应用纳排规则并保存判定及理由。证据不足或规则无法判断的记录进入待复核，不强行二分。
4. **获取全文**：优先使用可访问的 HTML 正文，PDF 作为备选；记录全文是否获取成功及来源。不得绕过访问控制。仅有摘要时，限制提取范围并明确标注证据层级。
5. **结构化提取**：提取通用文献 meta（如题名、作者、年份、来源、DOI、摘要）及本主题参数。每项重要参数尽量保留原始值、原文证据位置/摘录、原始单位、标准化值、转换方式和置信/复核状态；不得从缺失信息中猜值。
6. **规范化与交付前检查**：按已批准的数据字典统一单位、类别、日期和空值表示，同时保留原始信息；运行字段、范围、一致性、重复和证据完整性检查。
7. **人工审核交接**：生成待审清单，包括记录标识、待判断问题、已有证据、自动判断及原因。研究者确认后更新状态并保留审阅痕迹；经确认的数据再交给后续参数更新或计算模块。

## 交付

- 文献主表（CSV/XLSX）：一篇文献一条记录，含唯一标识、主题字段、筛选状态与审阅状态。
- 参数明细表（CSV/XLSX）：可采用“一篇文献 × 一个参数/实验/处理”多行结构，避免把多组实验压入单一单元格。
- 证据与来源：原始表述、页码/章节/表格位置或可定位链接；按需要提供逐篇 JSON。
- 运行日志：输入主题、检索式与来源、时间、纳排规则版本、去重与筛选计数、全文获取情况、提取/规范化版本。
- 质量摘要与待人工审核清单：缺失、冲突、低置信度、不可访问全文和其他异常及其影响。

具体表结构由主题数据字典确定。字段至少应包含稳定文献 ID、来源/标识符、筛选/审核状态、记录时间或规则版本；主题参数字段另附定义、类型、单位、允许值与证据要求。

## 检查标准

- **完整性**：必填字段有值或有明确缺失原因；输出结构符合本次数据字典。
- **唯一性**：重复识别有据可查，疑似重复保留合并关系而不是静默丢弃。
- **一致性**：单位、类别、日期、数值范围和跨字段关系符合主题规则；转换可逆向追踪到原始值。
- **可追溯性**：纳排决定、关键参数和规范化结果可追到来源及证据；无依据值不得标为已确认。
- **质量报告**：给出候选/纳入/排除/待审计数、全文获取率、字段缺失率、抽样复核结果及其样本范围。指标不可计算时说明原因，不虚构精度或覆盖率。
- **人工抽查**：按风险抽查纳入、排除和参数提取记录，特别关注边界案例、单位转换和多实验记录。

## 异常与处理

| 异常 | 处理 |
|---|---|
| 全文不可访问、仅有摘要 | 标记可用证据层级和受影响字段；尝试允许的替代来源；必要时交人工补充，不推断全文结果。 |
| DOI/题名缺失或疑似重复 | 保留原始记录和候选匹配，标记待确认；不因匹配不确定而自动合并。 |
| 纳排规则含糊或证据冲突 | 暂存为待人工审核，附规则和冲突证据；由研究者决定并记录原因。 |
| 参数未报告、单位不明或图表难以可靠读取 | 保留缺失/不确定状态与出处；允许人工转录，不自动补值或作无依据换算。 |
| 候选文献不足、来源不可用或检索失败 | 报告已覆盖来源、失败原因和对覆盖面的影响；建议调整方案，确认后再运行。 |
| 字段/类型校验失败或部分处理失败 | 保留原始输入与失败明细；隔离失败记录，避免整批静默丢失。 |

## SOC 示例映射（实例配置，不是通用规则）

`SOC-database-pipeline-clean/` 展示了一个土壤有机碳主题的具体实例。可将其配置映射为：

- **主题与范围**：中国地区、可定位样点的原始田间研究；限定研究对象和明确报告的 SOC 数据。
- **纳排判断**：地域、研究类型、样点可定位性、SOC 报告情况等按 SOC 项目规则处理；综述或不满足硬性条件的记录排除，信息不足者待复核。
- **meta / 参数字段**：地点、经纬度/定位信息、年份、作物、处理、施肥和 SOC 指标等，以 SOC 项目字段模板为准。
- **获取与提取**：HTML 优先、PDF 备选；记录全文获取状态，按论文/实验/处理保存数值和出处，避免把多个实验错误压成一条。
- **交付与把关**：整理 SOC 数据表、筛选/提取日志和需审核记录；经人工审核后，才作为参数或文献数据交给后续模块。

更换主题时，应重新定义范围、规则、字段、单位和审核阈值。SOC 样例中的检索源、地域限制、SOC 指标和排除条件不得自动套用到其他主题。

## 需对齐内容（初始版本）

1. 首期检索哪些来源，是否接受用户上传文献与既有清单？
2. 用户仅输入主题后，哪些范围/筛选/字段建议必须确认后执行？
3. meta 与参数明细的最小字段集是什么，是否按实验/处理拆分记录？
4. 目标数量指候选、纳入文献还是参数记录数，检索停止条件是什么？
5. 抽样复核比例、证据要求与可接受的提取质量如何确定？
6. 审核通过后的数据如何交给参数更新，以及哪些信息仍需该模块判断？
