# 师生协作功能（数据上服务器 · 角色 · 审核闭环）

> 状态：2026-11-25 实现并本地实测通过，已部署到 http://114.212.75.219:18700/
> 需求来源：主人 2026-11-25 的三点——数据落服务器、师生分角色、提交审核与批注闭环

## 一、用户看到什么

### 登录
测试码 `nailong` + **勾选身份**（学生 / 导师）。账号密码可留空（访客）。

### 学生
1. 正常做研究（文献、清洗、计算……），内容自动存到服务器（侧栏显示「☁ 已同步」）
2. 某一环节做完 → 状态条上点 **「提交给导师审核」** → 写一句提交说明 → 确认
3. 内容在这一刻**冻结**成快照发给导师；之后你继续改本地内容不影响导师看到的那版
4. 侧栏 **「◎ 我的提交」** 看状态：待导师审核 / 导师已通过 / 导师已打回
5. 被打回时：列表里直接露出导师最后一句意见，点开能看全部批注 + 「需要你修改」
6. 改完再点「提交给导师审核」→ 新版本，旧版本保留可追溯

### 导师
1. 登录时选「导师」
2. 侧栏 **「◎ 审核待办」**，红角标是待审数量
3. 点开一条：看到学生**提交那一刻冻结的**环节文档、执行记录、最近对话、学生说明
4. 写批注（可多条）→ 点 **「审核通过」**（学生那边正式解锁下一步）或 **「打回重做」**（必须写理由）
5. 学生端下一次轮询（≤5 秒）就会看到

## 二、技术实现

### 服务端 `tools/collab.js`
落盘在 `.workbench/collab/`（已被 .gitignore 忽略）：

```
accounts.json                     账号（盐化 SHA-256，与前端原格式兼容）
sessions.json                     token → { username, role, projectId, expiresAt }
projects/<projectId>/state.json   项目当前状态（服务端为准）
projects/<projectId>/submissions/<id>.json   提交快照 + 审核记录
```

要点：
- **原子写**：临时文件 → `fsync` → `rename`，崩溃不会留半个文件
- **队列串行**：同一资源（账号、项目状态、单条提交）的写入加锁，避免并发覆盖
- **乐观锁**：回写带 `baseRevision`，版本不符返回 409 而不是静默覆盖
- **拒绝符号链接**：防止数据目录被塞链接引到别处
- **角色校验在服务端**：学生调 `/review` 直接 403，不是靠前端藏按钮

### 接口 `/api/collab/*`

| 方法 | 路径 | 谁能用 | 作用 |
|---|---|---|---|
| POST | `login` | 公开 | 测试码 + 身份 → token |
| POST | `register` | 公开 | 建账号（需测试码） |
| GET | `session` | 已登录 | 校验 token，返回身份 |
| POST | `logout` | 已登录 | 注销 |
| GET | `teachers` | 公开 | 导师列表 |
| GET/PUT | `state` | 已登录 | 读/写项目状态（PUT 带 baseRevision） |
| POST | `submit` | **仅学生** | 冻结环节 → 待审记录 |
| GET | `submissions` | 已登录 | 学生看自己的，导师看全部 |
| GET | `todo` | **仅导师** | 待审列表 |
| GET | `submissions/<id>` | 已登录 | 单条详情（含快照） |
| POST | `comment` | **仅导师** | 追加批注 |
| POST | `review` | **仅导师** | 通过 / 打回 |
| GET | `changes` | 已登录 | 增量轮询 |

## 三、关键设计取舍

**提交即冻结快照**（而不是共用一份数据）
学生和导师同时改同一份会互相覆盖。冻结后学生怎么改都不影响导师看的版本，
导师的意见也能精确对应到"第几版"。旧版本永久保留。

**轮询而非 WebSocket**（5 秒间隔）
这个服务是零依赖裸 http，长连接要引入额外复杂度；课堂场景 5 秒够用，且断线重连天然免费。

**离线降级**
服务器连不上时退回纯本地模式（老行为），侧栏明确标「本机存储」而不是假装已同步。
课堂现场服务器抖一下就白屏，比数据没同步更糟。

**角色自选**（主人 2026-11-25 定）
测试码只有一个，登录时自己选身份。服务端按会话里的 role 校验权限，
但**挡不住刻意冒充导师的人**——这是课堂演示级，不是真实权限体系。

## 四、已知边界

1. **导师身份可自选**：知道测试码的人都能选"导师"。要真权限得接学校账号。
2. **所有学生共用一个项目**（`projectId = main`）。多人同时用会看到彼此的提交。
   要分项目需要前端加项目选择器 + 服务端按项目隔离（接口已支持 `projectId` 参数）。
3. **文件/附件不同步**：只同步项目状态（模块、文档、消息、执行记录元信息），
   上传的原始数据文件、`.workbench` 里的任务产物仍在服务器本机，不在同步范围内。
4. **无实时协作光标**：只有 5 秒轮询，不是 Google Docs 那种实时同步。
5. **AI 对话仍需各自填 API Key**：这是 2026-11-18 主人定的策略，未变。

```
11. 导师打回

JS 错误: none
```

### 测试中发现并修掉的两个真 bug
1. **注册不建会话**：只调了 `/register` 没登录，拿不到 token，进工作台后
   一直显示「本机存储」，学生提交的内容永远到不了服务器。
2. **轮询冲掉详情**：点开详情 120ms 就渲染出来了，1.8 秒后被 5 秒轮询的
   列表覆盖，用户看到的是"点了没反应"。改为看详情时只刷新统计行。
