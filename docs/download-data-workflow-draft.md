# 下载数据工作流（讨论草稿 v0.1）

> 讨论目标：定义“下载数据”模块的通用流程。此版聚焦把指定来源的数据可靠地获取并交付给“数据清洗”，不包含清洗、分析或计算。实际数据源和更新策略由每个研究任务配置。

## 定义

根据研究主题或任务要求，从用户指定/确认的数据源获取新数据或更新数据，保留未经清洗的原始文件与来源信息，形成可复现、可供下游处理的原始数据包。

默认不做字段改写、缺失值填补、单位转换或记录删除；如数据源本身提供多种下载格式，只做必要的格式选择并记录，不覆盖原始下载文件。

## 输入

### 必需

- 研究主题或数据用途：要获取什么数据、对应哪个研究对象/地区/时间段。
- 数据来源：平台、数据库、API、网页、文件地址或用户上传文件。若只给主题未指定来源，先列候选来源及差异，待确认后再下载。

### 可选

- 时间范围、地域/对象/变量筛选条件。
- 全量下载还是增量更新；若增量更新，指定上次成功时间/游标或其他更新依据。
- 输出格式、字段/变量清单、语言/版本偏好、每次下载数量或容量限制。
- 账号/API 凭证（通过安全配置提供，不要求写入工作流记录或明文日志）、已有数据/上次下载包。
- 下载频率、许可/引用要求、研究者特别关注的数据质量或版本。

缺少来源、权限或会改变研究范围的关键筛选条件时，返回具体待确认项。已经接入的数据源由程序核对官方目录、下载地址、名称与代码、单位及年份，不将这些可自动核对的技术信息作为用户必填项；不得猜测来源，也不得把未经确认的默认筛选伪装成用户要求。

### 已确认规则与程序核对的边界

- 用户决定研究范围，例如数据源、年份、商品、报告国/伙伴国与数量/金额。自然语言名称可以作为范围依据，不要求用户先查到官方代码或文件地址。
- 执行器负责将名称与官方字典匹配、定位文件、检查可用年份、要素名称/代码/单位、版本、大小和包内结构，并把真实核对结果写入任务记录；这些是执行步骤，不是下载前要求用户补齐的技术审批清单。
- 商品/国家使用官方字典的完整名称精确匹配，不按子串扩大范围；唯一匹配时自动采用并留痕。要素名称依官方字典归一大小写（例如 Import quantity/Export quantity）；同一明确要素对应多个官方代码时保留其全部变体，并核查实际单位，不把代码变体误当作业务歧义。只有出现多个不同含义的候选、无匹配、用户要求相互冲突，或缺少会改变范围的业务决定时暂停，展示证据和具体选项请用户选择。不能从记忆猜代码，也不能因未在方案抄写代码而忽略明确的商品限定。
- 用户当前明确指令和已确认规则优先于旧 AI 草稿中的建议、待确认标记和自设限制。旧草稿中“需提供官方代码/链接”“文件超过20MB需重新批准”等文字，不能覆盖当前已授权的官方整包下载及2GiB后台能力。确由用户明确设定的额外容量或范围限制仍须遵守；有新的范围变更时按平台修订和审核方案，不自动改写已审核文档。
- 普通对话可以说明平台下一步将自动核对哪些信息，但没有真实任务记录时不得声称已经联网验证或完成下载。

## 核验与验收（写在同一份下载方案中）

讨论下载方案时，代理同时草拟这一小节，与来源、范围和获取方法放在同一份方案里，供研究者一起审阅；后续讨论在原方案中修订并保留版本。研究者可以用自然语言提出要求，由代理整理，不要求研究者自行填写技术检查表。讨论、草拟和审核方案均不启动下载。

小节须说明**核什么、怎么核、谁核、怎样通过或退回**，优先覆盖下面三类共性问题，再按具体数据源补充：

| 核验对象 | 拟采用的核验方法与证据 | 通过或退回依据 |
|---|---|---|
| 与已确认方案一致 | 逐项对照来源、版本、研究对象/地区、年份、变量及筛选条件；保存实际文件、字段和来源字典的对应依据。单位先核对并记录实际口径，不在下载环节擅自换算。 | 明确条件均有对应证据；条件冲突、范围偏离或无法核实的项目列为待处理，不以“下载成功”代替符合方案。 |
| 完整且可读 | 核对实际格式与读取结果、文件/分页/批次是否结束、记录数及来源声明（可得时）；区分原始数据缺失、获取遗漏、空结果和无法读取。大小、SHA、CRC等检查用于文件完整性与追溯，不能单独证明数据科学正确。 | 按本任务确认的完整性要求判定；缺批次、未结束或不可读时说明已取得范围与缺口，提出补取、重取或退回调整方案的办法。 |
| 更新与变化 | 有旧版或增量基准时，对照版本/更新时间、字段及代码/单位口径、覆盖范围与记录数变化，记录新增、修订及空档；没有基准则如实标注首次获取或暂不可比较。 | 已解释的变化留痕；未解释的变化和连续性疑问列入待核，不自行认定最新、完整或与旧版可直接拼接。 |

**核验分工**：方案中区分执行器可自动完成并留证的检查、拟由独立复核代理或其他方法交叉核对的项目，以及需研究者作出的范围或验收判断。交叉核对须说明复核依据和如何处理分歧，不能仅因两个代理结论一致就认定正确；尚未接通的复核方式只写作拟安排，不声称已经运行。

**验收结论与退回**：拟定通过、部分完成、待核和退回的适用情形，列出问题、证据、影响范围和下一步动作。发现问题时保留原文件与历史，修订后按相同检查项复核；研究者确认方案与研究者确认实际结果分别记录。没有实际核验记录时，不写“已通过验收”，也不把点击审核方案视为文件质量已经合格。

**待确认边界**：可从已确认范围、官方声明及现有技术规则直接起草检查项；缺失率、允许误差、异常范围、预期记录数、抽样数量/比例等没有依据的标准不得自行设定。代理先给有理由的候选建议及适用条件，需研究者明确确认后才能作为本任务验收规则；不确定项集中列出，不逐项反复询问技术细节。既有官方目录、名称/代码、文件地址和包内结构的自动核对规则继续适用，不变成新的人工技术审批清单。

### 专业规则如何进入自动检查（2026-10-27）

**在同一份方案里确定规则**：讨论来源、范围和获取方式时，同时讨论模型需要注意的专业要求，例如指定指标允许什么单位、哪些字段不可缺少、什么情况下应为非空，以及有真实依据的值域或完整性要求。代理结合已有信息给出精简推荐，研究者核对业务含义和依据即可，不要求研究者自行填写技术配置。所有专业要求都要归入方案内的规则表；正文新增的要求不能只留在说明中并假称后台已执行。

**代理整理、整份审核**：方案使用固定标题 `### 专业核验规则`，表头为“编号 | 检查字段 | 检查方法 | 通过条件 | 适用条件 | 依据”。每条保留稳定编号，字段对应来源实际列名，依据可来自研究者明确决定、模型输入约定或具体来源说明。该节仅放规则表，说明写在前面或下一个同级标题中。未明确、无依据或暂不支持的要求保留为“人工判断”，说明缺少什么，不遗漏、不擅自定阈值。草稿占位不能当作已确认规则；审核整份方案后，保存的方案版本和校验值绑定本批规则。

**对实际文件执行**：后台读取冻结方案中的规则并生成执行清单，支持必需字段、非空、允许值、数值范围、唯一键和记录数检查，可按指标或对象限定适用记录。允许值可以核验单位或对象代码；数值范围和记录数只有存在已确认依据时才采用，不自动做单位转换或修复。CSV/TSV逐条扫描实际内容，记录适用行数、失败数、文件和行定位；没有适用记录、字段无法对应、条件不明确、方法不支持或格式未解析时，明确显示未执行或待决定，不能以零次检查当作通过。人工判断规则保留为待处理项。

**只看例外与依据**：正常检查折叠；专业规则不符合、互相冲突或拿不准时，沿用待处理清单展示要求、影响、原始依据、实际记录、已尝试处理和建议。研究者只作必要决定，不需从头逐行查全部数据。方案或文件改变后重新核验，不把旧报告或旧决定套到新证据；没有专业规则表的旧方案如实提示待确认，旧任务、文件、提取和导出结果保留，不因此自动重新下载。只有研究者明确确认无额外专业规则并记录本任务理由时，才可采用该决定，不能默认空表代表无需规则。

这一步是按已确认规则检查下载的数据，不自动修改、删除、插补或换算原值，也不声称已经覆盖所有科学适用性判断。规则讨论、草拟、审核或编译预览均不启动真实下载。

### 下载后核验与待处理清单（2026-10-27）

采用“智能体自动检查、人工只看未解决问题、最后统一确认”的验收流程。现有下载任务结束后，后台只读核验本地文件；旧下载任务可点击“核验已有文件”，不重新下载。核验报告、差异证据与每次人工决定分别留存，正常检查和已处理项默认折叠。

- **文件与范围**：实际大小与SHA-256对应原下载记录；CSV/TSV完整解析、检查结构及记录数。FAOSTAT另对照冻结的年份与官方代码条件扫描实际行，保留单位、名称映射及原包检查证据。普通文件尚无业务范围适配器时，展示实际字段/年份与来源，仅把未能自动判断的含义列为待决定；不假称已完成语义核验。
- **本任务专业规则**：读取本批冻结方案的专业规则表，对实际CSV/TSV执行支持的检查并逐条保留结果；无法执行或需要专业判断的要求直接列入待处理清单，不以自然语言方案存在代替检查记录。
- **更新差异**：仅从本会话历史批次选择同来源、同非年份筛选范围的基线，优先此前人工确认版本。FAOSTAT按报告国/伙伴国/商品/指标代码及年份对应记录；普通CSV无已确认键时只比较完整行多重集，不冒充准确的历史修订。新增汇总展示；历史值或标记修订、共同范围内记录减少、字段或单位变化、无法配对的重复键列为问题。已审核年份窗口的调整不当作删除、不重复询问。首次获取注明无历史基线；不同范围不混比。
- **人工清单**：每项必须包含问题、影响范围、具体依据、已尝试处理、建议及需研究者决定什么。需判断的变化/缺口可附理由接受或退回；损坏、读失败、校验不符等错误不能点击强行接受。没有自行设定异常阈值、科学误差或缺失率标准。
- **交接门禁**：问题处理完且核验就绪后，仍由研究者点击原有“确认文件并进入清洗”统一确认。后台按来源批次、冻结方案、报告版本、实际文件SHA与完整交付清单校验，不能只靠浏览器上的已确认标记通过。原件、旧版本、旧报告和决定依据保留；证据变化后须重新核验，原决定不自动套用。
- **格式边界**：记录级差异当前支持CSV/TSV。JSON、Excel、PDF、ZIP等按已有解析能力如实报告，未完整读取或无法比较时列明缺口，不以文件存在/校验值正确冒充内部内容正确。独立复核代理编排和科学适用性判定仍未全部自动接通。

下载或核验中的网络/文件错误保留具体任务原因和已完成内容。没有实际进行补取或重试时，不把“建议补取”写成“已补取”。本次功能开发和离线测试不构成真实下载授权。

## 网页当前支持的执行范围（2026-10-20）

使用流程为：讨论需求及专业规则并形成同一份下载方案 → 审核方案 → 点击「按方案开始下载」→ 平台执行获取任务 → 自动检查文件、更新差异及已确认专业规则 → 研究者处理待决定问题 → 点击「确认文件并进入清洗」。清洗模块收到文件副本、来源、方案版本、校验值及核验报告引用，不需要重新上传。

FAOSTAT 详细贸易矩阵 TM 已接入官方目录：自动定位官方全库ZIP、流式下载并保留完整原包，再按方案年份及明确条件筛选CSV；原列、文本代码、单位、Value和Flag保留，不换算、补零、去重或合并。用户不需要提供FAO下载链接或填写下载配置。年份必须明确；未限定的国家、商品和指标不筛选并如实登记。商品等名称由执行器与官方目录及包内字典核对，唯一匹配后按核得代码筛选；进出口数量/金额的要素与单位也由原包核对。明确限定不能忽略，字典歧义或缺失时保留已获取原包并列出具体待选项，不要求用户自行查链接或代码。当前单次支持1–5个年份。

下载模块只配置数据源、年份、地区、商品/变量、格式与验收。文献检索、论文筛选及原文数值提取在文献挖掘模块开展；此处既有旧文献批次保留为折叠历史记录，不会成为数据库下载的执行入口或待答问题。

方案已含公开文件地址时，也通过相同后台任务下载；每批最多5个、单个文件支持至2GiB，本地清洗交接也支持2GiB。网络中断或主动停止保留断点和已完成文件；网页刷新找回原任务；服务重启后手动继续。下载使用验证器与Range续传，来源不支持时从头重下；同版本FAO完整原包经大小和SHA复核后可复用。保留方案、来源、获取时间、大小、SHA-256、筛选行数及ZIP CRC检查记录。下载成功不等于人工验收通过。

旧手动文件链接弹窗与手动上传仍限20MB，仅供兼容；FAO自动路径不经过该弹窗。其他数据库的自动定位、登录、分页与认证接口仍需逐一接入，不能声称所有网站都能自动下载，也不把网页登录页面当作数据文件。普通AI对话只整理方案，实际执行由用户点击平台按钮发起。

## 执行

1. **解析任务**：从用户已确认内容读取目标数据、来源、筛选条件、更新方式和输出要求；保留自然语言范围，区别业务缺口与可自动核对的技术信息，形成将执行的下载方案。不把旧 AI 草稿的“待查证”文字当作新的业务限制。
2. **检查来源与访问条件**：确认来源可访问、允许当前用途和访问方式；按服务限制控制请求频率。凭证只用于请求，不输出到日志或交付文件。不得绕过登录、付费墙、验证码或其他访问控制。
3. **确定下载边界**：记录全量/增量策略、时间窗口、分页/游标、筛选参数与预期文件格式；增量模式确认游标连续性及是否需要补历史数据。FAOSTAT TM 从官方目录定位原包，核查字典与年份范围后执行明确条件；唯一匹配的名称/代码和要素/单位自动核对并登记，不重复索要技术确认。
4. **获取与暂存**：按来源支持方式下载文件或调用 API；分页/分批拉取时记录批次状态。先写入本次运行的独立暂存位置，避免失败的部分结果覆盖上次有效数据。
5. **记录来源元数据**：为每个文件/数据批次记录来源名称与链接/API（不含密钥）、请求时间、筛选参数、覆盖区间、格式、版本/更新时间、文件名、大小及可用的校验值/记录数。
6. **完成性核对**：确认 HTTP/API 状态、分页结束标志、文件可读性、记录数/页数与来源声明（若可得）一致；区分“成功但无新数据”和“下载失败”。
7. **交付原始包**：整理原始文件、来源清单与运行摘要；交给“数据清洗”模块，并说明数据结构未知项、部分失败批次和建议处理事项。

## 交付

- **原始数据文件**：保留源格式与原始内容，不被清洗结果覆盖；按任务/日期/来源组织并避免含糊命名。
- **来源清单（manifest）**：逐文件记录来源、获取时间、筛选/时间范围、文件格式、大小、记录数（可得时）、版本/更新时间、校验值（可得时）及下载状态。
- **运行摘要**：本次采用全量或增量、成功/失败批次、覆盖范围、新增/获取记录数、无数据状态、限制与未完成项。
- **交接说明**：供“数据清洗”使用的文件位置、字段/格式初步说明、来源声明的注意事项；不在这里擅自定义清洗规则。

如果来源只允许在线查询、无法保存原文件，则交付可复现的查询参数/请求批次信息和允许保存的响应数据，并标注无法留存的部分及原因。

## 检查

- **来源与范围**：来源及筛选条件与已确认任务一致，覆盖区间清晰。
- **下载完整性**：分页、批次或文件下载完整结束；失败批次没有被误报为成功。
- **文件可用性**：文件存在、大小非异常、格式可识别/可读取；记录数和来源声明合理（来源提供时）。
- **增量连续性**：更新游标/时间窗口无意外空档或重复窗口；若无法确认连续性，标注风险并询问是否补全量。
- **可追溯性**：每份原始数据都能关联到来源和本次运行参数；原始内容未被后续步骤改写。
- **安全与权限**：交付物、文件名和日志中无 API 密钥、令牌或不必要的个人敏感信息；用途符合来源许可。

这里按下载方案已确认的专业标准检查范围、字段、单位口径和具体条件，并对未确定的科学含义列出待决定项；不据此宣称数据已完全适合所有计算。字段改写、异常值处理、缺失填补和规范化仍由“数据清洗”阶段按单独确认的标准执行。

## 异常与处理

| 异常 | 处理 |
|---|---|
| 来源未指定、多个来源结果差异明显 | 暂不下载；列出来源、覆盖范围、格式/访问条件等差异，请用户确认。 |
| 官方字典无法唯一匹配已限定名称 | 保留原包及检查记录，列出实际候选名称、代码与匹配依据；只询问有歧义的选择，不退回要求用户自行查链接或补全全部代码。 |
| 登录/凭证失效、权限不足、付费或访问控制阻挡 | 停止受限请求，报告所需的合法授权/用户操作；不尝试绕过。 |
| 限流、网络中断或服务暂时不可用 | 按来源允许策略有限重试；记录失败批次和重试结果，避免无限重试或重复写入。 |
| 分页/批次部分失败 | 保留成功批次并标记整体为部分完成；不得当作全量完成交付，可在安全续传后补齐。 |
| 文件损坏、格式不支持或响应不是预期数据 | 隔离原响应及错误信息（注意脱敏），保留上次有效数据；请求确认格式或换用来源支持的导出方式。 |
| 增量游标丢失、时间范围不明或可能有空档 | 暂停宣称“最新/完整”；说明风险，询问从哪个基准继续或是否重新全量获取。 |
| 数据量/文件超过限制、来源只提供部分结果 | 交付可确认的范围与限制，建议缩小条件、分批获取或由用户提供合规的导出文件。 |
| 下载成功但 0 条新数据 | 标记为“成功，无新增数据”，保留查询范围及时间；不视为系统失败。 |

## 后续设计讨论（不作为已接入数据源的重复启动条件）

以下是平台后续能力的设计问题。已有任务按用户已确认方案与上面的当前执行范围推进，不逐条重新问用户，也不阻止已接入的FAOSTAT下载。

1. “下载数据”首期主要面向哪类数据？活动数据/API，还是也包括文献元数据、用户上传文件和网页数据？
2. 来源策略是严格由用户指定，还是允许系统根据主题推荐来源、用户确认后再下载？
3. 首期是否明确支持“全量 + 增量更新”，以及增量基准如何管理（时间戳、游标、文件版本等）？
4. 原始文件和 manifest 的默认交付形式/保存位置是什么？是否需要版本历史与失败批次留存？
5. 下载任务是否需要在进入“数据清洗”前由人工审核确认来源、范围或完整性？
