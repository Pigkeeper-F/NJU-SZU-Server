# 文献检索规则的逐项核查

入口在文献任务的「检索与执行设置」内。讨论并整理配置后，点击 **开始逐项核查**。

## 使用步骤

1. AI按四组展示实际配置：研究范围与条件、来源与检索式、纳排与交付要求、执行范围与边界；每组3–4项。
2. 每项可以 **确认这一项**、**修改**，或输入问题后点 **让AI解释**。AI说明原要求依据、当前设置、差异及影响，不替研究者确认。
3. 修改后点 **保存修改，待重新确认**。修改项及受影响项恢复待确认，其他确认保留。对话或已审核依据变化时需重新核查；旧依据和修改历史保留。
4. 通过上方分组按钮或 **上一组 / 下一组** 继续。**确认当前组**只确认当前组；**全部总览**查看还有哪些待确认项。
5. 全部确认后点击 **使用已确认配置**，回到任务点击 **按已确认配置检索**。应用配置本身不开始检索。

没有原始规则依据时，AI应明确说明无法判断一致性。AI说明失败时确认记录保留，可以重试解释。关闭弹窗只取消本次解释，不取消其他任务。

已有任务的整段文字规则会按完整行转为待核查列表；结构化内容以完整JSON文本保留，并提示检查格式，不自动删减或确认。纳入和排除规则各支持200项、每项2000字，超过时明确指出条数或具体长项，不会截断。打开失败时可点“重新尝试”或“返回检索设置”；原规则仍保留。

## 保存与执行

- 确认状态、逐项修改历史、AI说明和问答写入服务器 `.workbench/literature-rule-reviews/<id>/review.json`。当前文献任务保存核查记录指针和快照，刷新、切换后可继续。
- 复用规则新建文献任务时，复制的是配置草稿，不继承另一任务的确认状态。
- 修改来源、默认检索式等会使相关项目重新待确认；修改执行阶段也需重新核对受影响的处理设置。
- 服务端检查任务、会话、版本、全部确认状态、配置及阶段是否匹配。旧版本或未确认配置不能开始新的检索。
- 运行前将确认快照保存为检索任务目录内的 `rule-review-confirmed.json`，实际运行配置仍保存在 `run_config.json`；可从成果文件中回查。
- 已有历史检索任务继续沿原冻结配置续跑，不要求重新走新检索核查，也不会将新草稿混入旧结果。

浏览器的「备份」保存任务目录和核查指针；完整迁移还需保留服务器 `.workbench` 中的核查记录及原任务文件。不要将只有浏览器备份描述为包含全部服务器文件。

## 整理规则时连接中断

「从对话整理规则」包含提交整理和读取进度两步。后台已经受理后，读取进度断线也可能造成浏览器连接错误，不能由此断定整理没有提交。

- 已收到整理任务编号时，页面保存编号及所属文献任务，显示 **检查整理进度**。该按钮只读取原回复，不重新提交；刷新后仍可检查。
- 没有收到受理回执时，页面显示「受理状态未知」，不自动重复提交。**放弃本次等待**只清除页面等待记录，不停止后台，也不修改现有规则或确认记录。
- 对话、配置、会话或核查依据已经改变时，旧回复不会自动覆盖新草稿；后台运行记录丢失时如实提示，原草稿保留。
- 整理完成只产生待核查草稿。仍需逐项核查并应用，再由研究者点击开始检索。

这些恢复记录保存在当前浏览器；不等于后台的运行记录可跨服务重启恢复，也不能补回修复前未保存的整理编号。

文献规则整理的后续终态文字回复现另存于 `.workbench/literature-prepare-results/`，可在服务重启后按原编号只读获取。它不是可续跑任务或文件成果，不继承配置确认；修复前已丢失的回复不能补造。

修订现有规则时，省略字段保留原草稿；不会因只返回新检索式而清空来源、年份、范围或运行模式。各来源检索式按返回的来源逐项更新，省略项保留并提示未更新，明确 `{}` 才清空整组。首次创建且没有来源基线时仍必须给出来源，非法来源和纯说明文字不会被接受为配置。

收到回复后先保存原文，再尝试解析。格式失败可点 **重新读取这次整理结果**，只重读已收到的回复，不重复调用模型；旧回复已不存在时，再明确点 **结束本次并重新整理**。整理尚未应用时，页面标明下方仍是原草稿，并阻止按旧草稿开始新检索。

## 查看历史任务

历史列表的 **查看** 打开独立的只读详情窗口，读取该任务最新存档。窗口直接显示主题、状态、候选数、中断原因及文件下载；也可以查看启动时的已确认配置和实际检索式。没有生成文件时会明确说明。

查看和关闭窗口不会切换当前文献工作区、覆盖讨论或规则草稿，也不会继续检索。需要回到任务操作时，再明确点击 **载入此任务到工作区**；该工作区已有的草稿保留。

停止检索后已保存的候选 CSV/JSON 仍可下载。候选清单不是已经完成筛选、取得全文或完成提取的证据。

## 停止后修改并继续核查

- 已有新讨论整理出的草稿时，顶部显示 **继续逐项核查当前草稿**，在核查中保留最新草稿，不以旧运行配置覆盖。
- 从历史记录载入时，可以点击 **从历史配置建立修改草稿**。服务器核对原冻结记录后，创建属于当前工作区的新核查；原运行及确认快照保留。当前讨论依据发生变化时，相应确认需要重新核查。
- 已经保存的修改稿可通过 **回到修改草稿** 返回。旧运行的 **查看已确认配置** 始终展示旧快照。

建立草稿、导入历史规则及打开核查均不会开始检索。新配置需核查并应用，再点击开始。

## 当前草稿与原讨论

已有旧检索记录时，顶部的 **继续逐项核查** 直接核查当前已保存草稿；第2组显示实际的默认检索式和各来源专用式，不用旧运行快照替换。**查看已确认配置**仍单独显示旧运行依据。讨论更新但尚未成功整理写入时，页面会明确提醒；聊天里的建议不会被冒充为已经生效的配置。

检索式支持每条32,768字符；默认式和来源专用式同限。超限明确拒绝，不截断。重新整理时，模型省略来源专用式则保留原值并标明未更新，明确提供空对象才清空。

文献任务顶部新增 **讨论记录** 和 **保存讨论与草稿**。按工作区查看完整已发送消息、未发送输入和编辑中的方案，支持全文下载、回到原讨论，以及从本机历史版本恢复为新草稿。恢复不会继承执行确认或自动运行。

聊天追加和输入草稿变化会保存浏览器快照，并将完整内容备份到本机服务 `.workbench/literature-discussions/`；旧版本保留，空讨论不能覆盖旧非空版本。页面分别显示浏览器保存和本机备份状态，失败时显示原因。此后新增备份不能补造此前已丢失的原文；应按消息数、时间和全文核对旧记录是否仍在。

## 从历史任务继续讨论并更新规则

文献页面已统一使用 **从对话更新规则并核查** 作为整理入口，位于“检索与执行设置”操作栏左侧；普通草稿及历史续聊显示相同名称。它只更新待核查草稿，保存成功后打开核查，不会开始检索。读取进度、受理未知和整理失败时仍显示对应状态及恢复按钮。

历史详情固定显示 **继续讨论并更新规则**。如果当前已经在该运行或其修改草稿中，保留当前新检索式和讨论；否则载入对应文献工作区。不会因为进入讨论而创建核查确认、启动或恢复检索。

继续讨论模式下，原整理按钮显示为 **从对话更新规则并核查**。它先按当前已发送讨论生成并可靠保存新配置，再打开当前草稿的核查卡片。连接、生成、输入变化或保存失败时，不会自动打开旧配置冒充新整理结果。没有已保存讨论时先打开讨论找回入口，不制造历史聊天。

**讨论记录**可只读查找其他项目/模块的工作区、旧项目快照及启动前备份；跨工作区恢复需显式选择，恢复为新草稿，不继承确认或运行绑定。刷新时先保存冲突原件，再恢复缺失或明显陈旧的页面镜像；无法可靠备份时阻止覆盖原项目记录。

本机的 **旧核查记录片段**来自既有 review 的 context、sourceHistory 及逐项问答，仅表示实际保存的片段。列表不输出正文，读取详情展示原文与来源；不把这些片段拼成完整聊天或已确认规则。
