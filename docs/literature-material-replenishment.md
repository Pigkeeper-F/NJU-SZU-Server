# 沿用原候选补齐 PDF 与补充材料

## 用法

在已有候选的文献任务中，点击 **补齐PDF和补充材料**。平台使用原任务保存的候选、去重结果和冻结配置，建立关联的材料补齐记录；不会重新检索。

补齐记录只运行全文获取。它会校验并复用已保存正文和附件，补取缺少的正文 PDF，并核查、下载补充材料。补充材料保留网站提供的原格式。网页正文已保存时继续保留，其数量与 PDF 数量分别显示。

遇到登录、验证或机构权限问题时，保留问题页面和已保存文件。可以点击 **先留待处理，继续其他文献**：这篇登记在待处理清单中，其他文献继续获取，不因单篇受阻而整批停止。

人工登录没有倒计时。页面保留后可稍后处理，平台不会因为页面加载时限已过而自动关闭登录页或重复重试。页面加载和文件传输的超时只约束正在运行的获取操作。

其他可获取文献处理完后，平台列出需人工处理的文献、缺少的 PDF / 补充材料、原因和原页面入口。完成登录或权限处理后，明确点击 **我已处理，重新检查待处理文献** 才重试；已有文件仍经校验复用。补齐记录不自动进入提取、校验或导出。

## 原任务与重复操作

- 原任务的提取、校验、导出文件和材料状态保留原样，可从关联入口查看。
- 新材料在关联记录中登记。原提取、导出仍对应原材料版本，不会因补齐成功而自动更新。
- 对同一个原任务快照重复点击入口，会找回同一份补齐记录，避免重复创建下载任务；暂停或失败后由用户明确继续。
- 原候选数量、配置和去重文件通过摘要校验关联；补齐不能被改成新检索或自动提取。
- 已下载文件须经本地文件和登记信息核验后复用。文件缺失、校验失败、无法读取或没有权限时，分别标注原因。

## 完整度

“材料获取阶段已结束”表示这轮处理结束。每篇是否取得 PDF、附件是否已核查和下载、是否可读取，仍以每篇材料清单为准。缺少 PDF 时，已有网页正文不会被称作已取得 PDF。

## 本地接口

`POST /api/literature/replenish-materials`，请求仅含原任务 `id`。接口返回关联材料记录。关联记录的 `materialReplenishment.parentJobId` 指回原任务，运行边界固定为 `fulltext`。

Python 补齐入口为 `literature_fulltext.py --resume --replenish-materials`，只适用于具有有效 `materials-basis.json` 的关联记录。

材料补齐记录通过 `POST /api/literature/advance` 的 `deferAccess: true` 选择逐篇留待处理。该选择随记录保存，普通继续不会重试已留待处理的文献。`retryDeferred: true` 表示用户明确要求重新检查。

待处理结果保存为 `fulltext/manual-actions.json`、CSV 和 Markdown。`POST /api/literature/material-action-page` 只接受关联记录 `id` 和已登记的 `paperId`，用于打开该篇保留的任务页面。待人工处理期间不启动自动倒计时或自动重试。
