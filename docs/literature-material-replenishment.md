# 沿用原候选补齐 PDF 与补充材料

## 用法

在已有候选的文献任务中，点击 **补齐PDF和补充材料**。平台使用原任务保存的候选、去重结果和冻结配置，建立关联的材料补齐记录；不会重新检索。

补齐记录只运行全文获取。它会校验并复用已保存正文和附件，补取缺少的正文 PDF，并核查、下载补充材料。补充材料保留网站提供的原格式。网页正文已保存时继续保留，其数量与 PDF 数量分别显示。

已有网页正文但缺 PDF 时，先检查同篇详情页或阅读器中的实际 PDF 入口。确认入口和文献身份后，优先通过原页面的按钮、菜单及链接完成下载，保留网站要求的点击和来源会话；等待文件保存并登记，再继续检查补充材料。正文下载前不先访问其他补材入口，补材的登录或加载问题单独保留，已经保存的正文继续复用。

遇到登录、验证或机构权限问题时，保留问题页面和已保存文件。可以点击 **先留待处理，继续其他文献**：这篇登记在待处理清单中，其他文献继续获取，不因单篇受阻而整批停止。明确的 404、坏链接、已完成检查但没有可用文件等非认证问题，记录原因后跳过，不放入登录清单，也不自动重复请求。

页面按文章内容、实际 PDF 入口、附件链接和文件进度等待稳定，不只等固定几秒或一分钟。导航计时结束后仍会检查页面是否已经可用；有实际进展可继续等。若长时间无进展或达到活动预算仍未就绪，记为 **页面尚未就绪**（`page_not_ready`），保留窗口供稍后显式检查，继续其他篇。未就绪不等于缺材料，不能据此关闭页面。阅读进度条不当作文件下载进度。

文件下载完成并校验、登记保存后，及时关闭本任务对应的页面。正文 PDF 已保存但补材仍有缺口时，同样关闭已完成的下载页；缺口继续列在“已跳过材料缺口”中。关闭前检查实时页面：登录、验证、权限、文件生成和下载中的页面保留，共享认证页及用户其他页面不关闭。

人工登录没有倒计时。页面保留后可稍后处理，平台不会因为页面加载时限已过而自动关闭登录页或重复重试。页面加载和文件传输的超时只约束正在运行的获取操作。

其他可获取文献处理完后，平台分别列出需认证或等待就绪的文献和已跳过的材料缺口。完成登录、权限处理或确认页面就绪后，明确点击 **我已处理，重新检查待处理文献** 才重试待处理清单；已有文件仍经校验复用。补齐记录不自动进入提取、校验或导出。

## 原任务与重复操作

- 原任务的提取、校验、导出文件和材料状态保留原样，可从关联入口查看。
- 新材料在关联记录中登记。原提取、导出仍对应原材料版本，不会因补齐成功而自动更新。
- 对同一个原任务快照重复点击入口，会找回同一份补齐记录，避免重复创建下载任务；暂停或失败后由用户明确继续。
- 原候选数量、配置和去重文件通过摘要校验关联；补齐不能被改成新检索或自动提取。
- 已下载文件须经本地文件和登记信息核验后复用。文件缺失、校验失败、无法读取或没有权限时，分别标注原因。

## 完整度

“材料获取阶段已结束”表示这轮处理结束。每篇是否取得 PDF、附件是否已核查和下载、是否可读取，仍以每篇材料清单为准。缺少 PDF 时，已有网页正文不会被称作已取得 PDF。

## 本地接口

`POST /api/literature/replenish-materials`，请求仅含原任务 `id`。接口返回关联材料记录。关联记录的 `materialReplenishment.parentJobId` 指回原任务，运行边界固定为 `fulltext`。

Python 补齐入口为 `literature_fulltext.py --resume --replenish-materials`，只适用于具有有效 `materials-basis.json` 的关联记录。

材料补齐记录通过 `POST /api/literature/advance` 的 `deferAccess: true` 选择逐篇留待处理。该选择随记录保存，普通继续不会重试已留待处理的文献。`retryDeferred: true` 表示用户明确要求重新检查。

用户明确要求重新处理旧缺口时，可同时传 `retrySkipped: true`；普通继续仍不重复尝试已跳过项。`firstPaperId` 只调整本轮材料队列的优先顺序，不改变冻结候选或去重文件；指定项必须属于本轮明确重试的范围。原跳过原因在实际重新处理前写入 `fulltext/material-retries.json`，已保存文件继续按摘要复用。

认证及尚未就绪的结果保存为 `fulltext/manual-actions.json`、CSV 和 Markdown；已确认需跳过的缺口保存为 `fulltext/skipped-materials.json`、CSV 和 Markdown。`POST /api/literature/material-action-page` 只接受关联记录 `id` 和待处理清单中的 `paperId`，用于打开该篇保留的任务页面。待人工处理期间不启动自动倒计时或自动重试。
