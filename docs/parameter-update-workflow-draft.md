# 参数更新工作流（讨论草稿 v0.1）

## 定义

将来自文献挖掘、数据库或用户提供的参数整理成符合计算要求的新参数版本，明确来源、适用范围和替换依据，并评估更新影响。

## 输入

- 必需：待更新参数及来源证据、计算所需参数定义。
- 更新已有参数时：旧参数表、版本及更新目标。
- 可选：地域/时间/对象适用范围、单位、不确定性、参数选择/汇总规则、参考结果与验收标准。
- 若参数尚未获取，形成需求交给文献挖掘或下载数据，再返回本模块。

## 执行

1. 明确参数含义、单位、所需粒度与更新原因。
2. 核对候选参数的来源和证据，区分已审核、待审核及缺失记录。
3. 对齐参数名称、单位、类别与适用范围；多个候选值按确认的选择/汇总规则处理。
4. 形成新旧参数差异和适用范围变化，保留不确定性信息。
5. 完成检查与必要的人工审核，生成独立参数版本。
6. 将参数版本交给计算；需要时在相同活动数据与方法下比较新旧结果。

## 交付

- 参数表与字典：参数 ID、值、单位、适用条件、来源、证据和审核状态。
- 版本与变更清单、选择/汇总依据、对齐规则。
- 缺失/冲突清单，以及已执行的更新影响分析。

## 检查

- 参数定义与计算输入一致，单位转换和类别匹配有依据。
- 来源证据完整，参数在允许范围内，适用对象/时期可明确判断。
- 多个候选值的选择可复核；不确定性和相关假设没有在汇总时丢失。
- 新旧差异与结果变化可追踪，旧版本保留。

## 异常

- 参数缺失或证据不足：交文献挖掘/人工补充，标记无法更新的范围。
- 多来源冲突：展示候选及差异，按规则处理或交人工裁定。
- 适用范围不匹配：暂停替换，明确是否需要新的参数或经批准的外推。
- 更新造成异常结果：保留候选版本，回查参数选择、单位、对齐和计算方法。

## 需对齐内容

1. 哪些参数需要支持，首期参数表的粒度和结构是什么？
2. 多篇文献/多来源参数如何选择，是否允许加权汇总或 meta 分析？
3. 参数发布前哪些项必须人工审核？
4. 是否默认比较新旧计算结果，异常变化阈值如何确定？
5. 参数更新与文献挖掘的调用关系、审核顺序和返回机制如何设计？
