# 数据清洗工作流（讨论草稿 v0.2）

当前程序入口与使用方式见[数据清洗：检查、执行与复现](cleaning.md)。2026-10-29已接通固定CSV/TSV/Excel检查、输入与规则冻结、项目脚本执行、独立核验及原脚本复现；以下科学规则与验收仍需按项目讨论，不因平台实现而自动获批。

## 定义

围绕项目目标，对指定范围内的原始数据执行明确的清洗步骤，遵循本项目特殊说明，形成满足目标的数据集和处理记录。自然语言要求先整理成可执行方案；每一步的输入、操作、输出和检查方式都应清楚，原始数据与结果之间保留对应关系。

## 输入

### 必需

1. **目标**：本次清洗要解决什么问题、数据最终用于什么任务、希望得到什么结构或结果。例如“整理成地区—年份面板，供既有计算程序使用”。
2. **原始数据（下载 / 本地文件）**：明确来源路径，可来自下载数据模块或用户已有的本地文件；说明对应文件/数据集及其版本、格式和必要字段含义。来源信息未知时标记未知，不强制用户先走下载流程。
3. **数据范围（需要处理哪些内容）**：明确哪些文件、工作表、字段、记录、时间、地区或对象参与处理，以及需要保留和不参与处理的内容。“全部处理”也应落实到具体数据对象。
4. **清洗步骤**：用户可以提供步骤，也可以描述问题后由 AI 协助拟定。作为执行前必需的方案，步骤需覆盖顺序、适用范围、操作、规则及输出；用户无需在第一轮就给出完整技术方案。
5. **本项目特殊说明**：记录通用规则之外的项目约束，例如编码惯例、特殊缺失标记、必须保留的记录、单位含义、历史口径和下游要求。没有特殊要求时明确记录“无”；不把一般经验直接当成本项目规则。

### 可选

- **验收标准**：用户可指定字段完整度、允许缺失比例、记录数量、数值容差、参考样本或其他通过条件。
- 未提供验收标准时，仍可拟定方案并执行已确认步骤；按目标与步骤做基础核对，报告检查结果和未判定事项。AI 可以建议验收标准，但不能将建议自动当作用户批准的阈值，也不能宣称已通过未定义的验收。

### AI 收集输入的方式

先结合已有对话整理五项必需内容的已知信息与缺口，优先补目标、原始数据和范围，再协助细化步骤与特殊说明。每轮只询问推进所需的关键问题；已有明确答案直接复用。验收标准缺失不作为启动工作的阻断条件。

原始本地路径用于识别来源。Web 的本机 Codex 模式可读取用户上传到任务目录的文件副本；仅提供电脑上的路径不等于文件已上传或读取。API 对话模式需要用户提供字段、样例或执行结果。只有实际读取成功时才能报告数据概况。

## 清洗步骤如何定义

清洗步骤由目标、实际数据问题、处理范围和项目特殊说明共同决定。下面是供选用的操作类别，不要求每个项目执行所有类别，也不固定为单一顺序。

| 操作类别 | 需要具体说明的内容 |
|---|---|
| 读取与结构整理 | 文件格式、编码、工作表、表头位置、宽/长表结构、多文件关系和解析方式 |
| 范围筛选 | 保留哪些字段/记录/时期/对象，筛选条件、范围外数据去向 |
| 格式与类型处理 | 文本空白、日期、数值、标识符与类型转换；如编码前导零是否必须保留 |
| 重复与关系处理 | 重复的业务判定键、完全重复与多次观测的区别、合并/保留方式及连接基数 |
| 缺失处理 | 哪些值代表缺失、各字段保留/标记/删除/插补策略及适用条件 |
| 异常与冲突处理 | 异常依据、跨字段矛盾、冲突来源优先级，以及标记/隔离/修正方法 |
| 单位与口径统一 | 原单位、目标单位、转换公式、类别映射、时间/空间尺度和汇总口径 |
| 输出整理 | 字段顺序与命名、数据粒度、排序、格式、字典和记录对应关系 |

每一步至少按以下模板描述：

| 项目 | 说明 |
|---|---|
| 步骤编号与名称 | 本步骤解决的问题，以及与其他步骤的先后依赖 |
| 输入与范围 | 使用哪个数据版本、文件/表、字段和记录条件 |
| 操作与规则 | 具体判定条件、操作方法、参数或公式；存在歧义时列出待确认项 |
| 项目约束 | 本步骤必须遵循的特殊说明和例外 |
| 输出与变更 | 结果结构，新增/修改/合并/删除/隔离什么，如何关联原记录 |
| 检查与异常 | 如何判断操作正确，不能处理的记录如何标记和交接 |

例如，“处理重复数据”需要进一步确定：按哪些字段判定重复，多次观测是否属于合法记录，冲突值如何处理，保留哪条，以及如何核对处理前后的数量。不能仅凭字段相同或经验自动删除。

执行前输出一份具体方案，标明已确认步骤、建议步骤和待确认规则。对删除、插补、替换以及改变统计口径的动作，先对齐关键策略；已确认规则可按其明确范围继续推进。

## 执行

1. **明确任务**：整理目标、原始数据、数据范围、清洗步骤和项目特殊说明；记录可选验收标准是否提供。
2. **了解数据**：在实际有数据或执行结果时，核对结构与范围，统计适用的类型、缺失、重复、数值范围及无法解析情况。仅有样例时说明其覆盖局限。
3. **细化方案**：按步骤模板将要求转成可执行规则，安排依赖顺序；说明影响范围、项目例外及待确认策略。
4. **逐步处理**：按已确认方案执行，记录每一步的输入/输出、修改数量、隔离项与规则版本。Web 本机 Codex 的执行模式可生成代码并处理任务目录内文件；查看/拟方案模式只读取与分析。API 对话模式由用户执行建议代码并提供结果。有实际证据才记录为已执行。
5. **检查与修订**：核对每一步及总体目标；若提供验收标准，则另外逐项判定。发现问题时定位具体步骤，修订规则后重做受影响部分。
6. **交付与交接**：汇总清洗数据、处理记录和检查报告，将仍需科学判断或无法处理的事项交给人工审核或下游模块。

## 交付

- 实际执行后：清洗数据及字段字典（类型、单位、编码、空值含义）；对话阶段可先交付方案或代码，并注明执行状态。
- 任务说明：目标、原始数据来源/版本、处理范围、项目特殊说明。
- 清洗步骤及规则版本、处理日志、原始记录到输出记录的对应关系。
- 处理前后质量对比、删除/修改/合并/隔离记录及理由。
- 基础检查报告、待人工确认事项；提供验收标准时另附逐项验收结果，未提供时明确注明。

## 检查

- **目标与范围**：结果符合本次目标；参与处理的文件、字段和记录与约定一致，范围外内容的去向明确。
- **步骤落实**：按已确认顺序和规则处理，项目例外得到保留，未执行或失败步骤有记录。
- **数据核对**：按步骤检查类型、缺失、重复、单位和跨字段关系；输入记录与保留、合并、删除、隔离记录之间可核对。
- **可追溯性**：插补、修正和转换值能追溯到方法与原值；相同输入和规则可复现。
- **可选验收**：只按用户提供或明确确认的验收条件判断通过与否；基础检查与正式验收结论分别报告。

## 异常

- 目标或数据范围不明确：先列具体解释和影响，补齐后再确定相关步骤。
- 数据内容不可用或文件无法解析：说明缺失材料/失败范围，提供读取建议，不能宣称已检查或清洗。
- 字段含义、单位或步骤规则未知：标记并暂停受影响操作，其他明确部分可继续推进。
- 项目特殊说明与通用规则冲突：明确冲突，按已确认的项目约束修订步骤。
- 缺失/异常过多：报告实际情况与影响；有确认阈值时判定是否超限，否则提出待决问题。
- 误删风险、步骤失败或验收未通过：保留原数据和处理记录，定位并修订受影响步骤。

## 需对齐内容

1. 首期数据类型、目标结果结构与下载/本地文件的实际接入方式是什么？
2. 数据范围如何在界面表达：按文件/工作表/字段选择，还是先由自然语言定义？
3. 清洗步骤是否支持逐步预览、调整顺序和局部重跑，已有方案如何复用？
4. 项目特殊说明采用自由文本还是结构化例外规则，冲突时如何确认？
5. 可选验收标准是否提供推荐模板；用户确认后如何保存并复用？
6. 逐记录变更日志需要保留到什么粒度，清洗交付后哪些情况必须人工审核？
