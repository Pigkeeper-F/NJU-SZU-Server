# 知网同名结果逐条核对与详情续接修复

原知网生产任务在第六批遇到多个完全同名条目后暂停。人工点击通常打开新的详情标签，而旧恢复流程仍检查已绑定的检索页，因此继续时会再次报告同名歧义。此停点的日志没有网络超时记录。

研究者授权遇到此情况逐条打开核对。本次仅修改文献定位和摘要回源：在能证明当前结果页已完整显示本次检索结果时，固定同名行队列，串行点击正常题名入口，读取各详情的题名、作者、年份或可靠文献编号。先保存定位证据，再关闭该条临时详情。只有唯一版本与原候选身份符合时，才重新打开该条并交回原摘要读取和篇关摘筛选流程。不同版本的定位不匹配不是科学排除结论，也不会将所有同名项直接下载为目标 PDF。

显式继续还可认领原绑定页的直接子详情，但须验证页面来源关系、同篇身份、唯一性及其他任务的页面占用。无可靠关联的标签页不借用。当前页是否完整无法确认、身份未知、多匹配、验证码、登录、权限或页面未就绪时，保留原页和断点。关闭失败后恢复也会重新检查该详情的身份及访问状态。

逐条队列与阶段进度写入原任务绑定；时间预算到达时，只有同一题录、同一固定队列的持久进度严格增长，平台才自动继续下一段。进度上限为 153，时间戳变化、重复尝试、身份或队列改变均不算新增进展；真实访问限制及无进展继续暂停。摘要模式仍不点击 PDF，不读取文件内容，不改既定科学纳排或待定 PDF 分流。

验证记录：人工恢复与同名逐条核对新增 34 项离线检查，覆盖正常定位、作者年份冲突、多匹配、分页不明、真实验证、关闭失败、恢复不重复点击、预算进度和父子页清理。相关 Python 定向检查共 177 项通过，筛选管线及分批筛选两组 JS 检查通过，独立复审无剩余阻断。旧 HEAD 在新增主反例中仍停于同名歧义；内存移除关闭恢复前的新鲜状态检查后，验证页和加载页反例均失败。首组包含 LocalDOM 的运行长时间无输出后已结束，不计作通过；实际通过范围为明确选择的离线类。

现场验证沿原知网生产任务继续。修复前已保存 3,814 条候选、50 篇判定及 29 份 PDF；冻结候选与运行配置的 SHA256 基线保存在本机运行证据目录。材料获取、科学资格与检索覆盖分别核验，不因启动或下载成功就称全库完成。运行数据和浏览器状态不进入 Git。

修复已加载至本机平台 18125，并通过原任务的继续接口恢复至全文获取阶段。现有续跑流程会复核前面批次并复用已存 PDF，尚不能直接从原批次游标继续；原停点现场结果另行追加，不能以接口返回 running 代替停点验收。

2026-11-03 北京时间 13:55，原任务已到达第六批的 CNKI-1698，保存 5 条完整同名结果队列并正常打开第 1 条，随后检测到安全验证并保留原页和逐条断点。原生窗口清单同时显示“安全验证 - Google Chrome for Testing”；窗口工具仍无法读取该窗口详情。已请研究者在原页完成验证。此时仍为 50 篇已筛、29 份 PDF，候选及冻结配置 SHA256 不变；证明新逐条路径已实际进入，但未越过该篇，尚不宣称完整现场验收。真实验证继续按原规则等待人工处理。

随后研究者回复“验证好了”，并要求交由流程智能体执行、无需本聊天持续盯跑。已通过原任务继续接口恢复为 running/fulltext、attention=null。后续由平台按既定规则推进，结果以其持久台账为准；本次恢复不等同于已证明该篇核完。
