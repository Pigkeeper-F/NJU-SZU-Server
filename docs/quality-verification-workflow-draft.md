# 数据、建模与结果的质量核查草案

日期：2026-10-26。状态：**实现审计与待讨论方案，不是已经上线的质量保证功能，也不替代具体研究项目的科学规则确认。**

## 1. 当前实现的结论

流程入口、方案确认、文件执行和部分程序检查已经具备；把人工经验固化为可复用规则、逐项保存证据、独立复算、多智能体交叉检查和下游质量门，尚未形成完整闭环。

| 环节 | 已有能力 | 尚未落实的部分 |
| --- | --- | --- |
| 数据获取 | 通用下载检查响应、文件非空和格式，记录大小与SHA；流式下载核传输长度。FAOSTAT TM另有官方来源、字典代码、年份筛选、CSV结构、ZIP CRC等检查。文献PDF有文件及身份核对。 | 通用研究范围、预期单位、缺失、重复、覆盖格、汇总数值、科学适用性验收；交接时绑定逐项科学检查结论。 |
| 建模与计算 | 已有代码/输入上传、讨论与确认方案、直接运行或按确认方案修改、日志及独立输出。 | 跨任务可复用的公式/单位/映射验证器，人工算例基准，模型适用性验证，独立复算，按明确容差作通过判定。提示词要求不等于每项检查均已实施。 |
| 结果核查 | 可提供核查原则或标准文件，让AI只读查看计算输入、代码、日志及输出并讨论问题。 | 固定检查项的机器结果、运行与规则版本的强绑定、独立参考实现、统一审查报告及问题关闭后才能发布的门禁。 |
| 人工审核与互审 | 已有方案批准、结果确认、环节通过/打回和文字记录。 | 逐项签认、审查人和证据、独立复核任务编排、分歧裁定、修改后自动失效与复验。 |

软件测试通过表示相应程序行为通过测试；具体数据、模型和研究结论仍须按本项目的证据验收。

## 2. 把人工经验写成规则

每条经验至少回答以下问题，形成其他人可照做的检查卡：

| 内容 | 需要记录什么 |
| --- | --- |
| 对象和版本 | 哪个任务、输入文件、数据批次、程序、参数、规则版本和输出 |
| 检查目的 | 要排除哪一种具体错误 |
| 操作方法 | 打开哪个原文件/工作表/页码；执行哪项断言或独立算例 |
| 预期与依据 | 预期单位、范围、关系或基准值来自哪份已确认方案、官方说明、公式或原文 |
| 通过条件 | 精确相等或何种允许误差；容差的理由与确认人 |
| 实际证据 | 实际值、差值、样本选择、原文位置、脚本、日志与产物 |
| 结论和处理 | 通过、不通过、待确认、不适用；问题回到哪个环节，修正后怎样复验 |

缺少预期值、适用条件或容差依据时标记“待确认”，不能让智能体自行补一个阈值后宣布通过。“不适用”也要说明原因。

## 3. 数据获取与交接检查

| 规则编号 | 怎样检查 | 预期依据与证据 |
| --- | --- | --- |
| D01 来源及版本 | 对照确认的来源清单、官方数据说明和实际请求记录，核对数据集、发布时间及修订版本。 | 已确认来源；保存网址、版本、请求条件和时间。SHA用于识别文件是否改变，官方提供校验和时另作比对。 |
| D02 获取完整性 | 核对真实下载完成、传输长度、文件可打开、压缩包CRC和文件清单；有分页的核对页码/批次及明确结束状态。 | 来源所提供的长度、文件列表、批次或末页证据；无法确认全量时标记范围限制。 |
| D03 研究范围 | 比较预期与实际的年份、地域、对象、分类及覆盖组合，输出缺失和多出的组合。 | 研究者确认的覆盖范围；来源确实不报告的组合单列说明，不能补造记录。 |
| D04 字段与单位 | 对照官方字典和本项目数据约定，核对字段语义、单位、统计口径及换算过程。 | 字典、字段映射、原单位与目标单位；单位换算记录公式与依据。 |
| D05 表内质量 | 统计缺失、重复键、非法数值、异常值、质量标志，列出受影响记录。 | 本项目允许的缺失和重复处理规则；异常先保留并待核查，不自动删改。 |
| D06 数量及总量 | 按适用的分组核对记录数量、分项与合计；对照官方汇总或人工核对样本。 | 同版本同口径的独立基准和已确认容差。合计口径不一致时不强求相等。 |
| D07 文献数值 | 从原正文及实际补材逐项核对数值、指标、处理组、时间、n、单位、SD/SE/SEM及出处。 | 本项目确认的提取规则；保存页码/表号/工作表/单元格和原值，不把摘要当作全文。 |

下载模块负责取得原件及获取记录；清洗模块可以执行表内质量检查。**交接结论应展示两部分各检查了什么，不能因职责分开而遗漏科学适用性。**

## 4. 建模与计算检查

| 规则编号 | 怎样检查 | 预期依据与证据 |
| --- | --- | --- |
| M01 方法与适用性 | 将研究问题、对象、输入条件与模型假设和适用范围逐项对应，标出外推。 | 已确认方法及其原始依据；研究者确认适用范围或外推理由。 |
| M02 公式与维度 | 将关键公式与代码对应到具体函数，核对参数含义、单位、转换、时间及空间尺度。 | 方法说明及经确认的字段约定；量纲核对和代码位置。 |
| M03 映射与连接 | 检查连接键、连接基数、未匹配/多匹配数量和前后行数，核对代表性记录。 | 确认的对齐方案；避免意外多对多扩增、漏项或重复累计。 |
| M04 人工算例 | 用研究者已核对的小样本输入，通过手算或独立实现得到预期结果，再与主程序逐项比较。 | 保存算式、输入值、预期值及容差；预期值不能由待验证主程序自行生成。 |
| M05 边界与失败情况 | 检查缺失输入、零值、极端值、非法单位等在模型中的实际处理。 | 模型适用域和确认的缺失策略；零值/负值等是否合理由领域规则决定。 |
| M06 参数与敏感性 | 检查参数来源、版本和适用条件；在有依据的变动范围内分析关键结果如何变化。 | 已确认参数区间与设计。结果稳定不能单独证明模型正确；显著变化需要解释。 |
| M07 独立验证 | 适用时用未参与拟合或调参的数据验证，检查数据泄漏、基准模型及误差表现。 | 研究设计、独立验证数据和提前确定的指标/阈值；无验证资料时如实标记未验证。 |

## 5. 最终结果的可靠性依据

| 规则编号 | 怎样检查 | 预期依据与证据 |
| --- | --- | --- |
| R01 基本结果 | 检查文件、行列、缺失、NaN/Inf、单位、范围及适用的守恒/边界关系。 | 已确认输出约定与数值检查规则。 |
| R02 独立复算 | 用独立公式实现或人工算例复核关键结果，定位所有超容差差异。 | 输入、公式依据、独立脚本及逐项差值。复算检验实现一致性。 |
| R03 可重复性 | 在记录的代码、环境、参数和输入版本下复现；随机过程记录种子并按确认的误差方式比较。 | 运行清单、依赖版本、日志和复现结果。 |
| R04 外部一致性 | 与实测、官方汇总、独立研究或其他适用基准比较，核对口径并解释差异。 | 基准的来源及独立性；同一数据的不同加工版本不能冒充独立证据。 |
| R05 不确定性 | 按研究设计报告误差、参数及输入不确定性，说明情景假设、敏感性和证据缺口。 | 已确认的不确定性方法及适用前提，不随意给置信区间。 |
| R06 交付一致性 | 核对结果表、图、报告中的数字、单位、筛选范围和版本一致。 | 可追溯到同一通过版本的表、图和报告。 |

可靠性由这些适用检查的证据共同支持。没有统一适用于所有项目的“可靠率”；容差、抽样规模和必须通过的规则需要按任务确定。

## 6. 人工与智能体结合的候选流程

1. **研究者定义验收**：选定适用规则、基准、容差、样本和阻断等级，提供已知正确及已知错误的例子。
2. **执行智能体A**：完成本次已授权工作，交付原件、代码、配置、结果和日志，不自行批准自己的成果。
3. **程序检查器**：运行可编码的断言，输出实际数值、预期条件和失败位置。
4. **复核智能体B**：读取同一冻结输入与验收规则，独立检查或复算关键项；先提交自己的检查结果，再查看A的解释，减少照抄结论。
5. **差异核对**：合并A/B、程序及人工检查的逐项证据；分歧保留，按原因回到数据、规则、参数、映射或代码。
6. **人工裁定**：研究者处理科学适用性、口径冲突和未决事项，记录证据与理由。不同模型的一致意见只作为辅助信息，不能按多数票替代原始证据。
7. **受影响项复验**：修正后只重跑受影响规则及其下游检查，确认阻断问题关闭后发布通过版本。

重复核对必须增加独立信息，例如原件证据、另一个公式实现、已核对算例、实测数据或变更后的测试；仅反复询问同一个模型不能作为新增验证证据。

## 7. 记录、门禁与复用要求（待实现）

- 每次检查保存：对象版本、输入/代码/参数/规则校验值、规则ID、检查器版本、实际值、预期条件、容差依据、证据文件、检查人/智能体及时间。
- 逐项状态：未检查、通过、不通过、待确认、不适用。失败需另记录阻断等级；汇总状态不能掩盖未检查项。
- 阻断问题未解决时不得把该版本标为可用于正式下游分析。可以导出问题清单或明确标记的部分结果，不能把这种导出当作验收通过。
- 方案批准、程序运行成功、科学验收、下游交接分别显示。人工批准也不能直接抹掉失败记录；如允许例外，需明确记录授权依据及适用边界。
- 绑定的文件、代码、参数或规则改变后，使受影响的结论失效，记录需复验哪些项；历史结论和文件保留。
- 已完成且版本、对象范围与规则仍匹配的检查直接复用。新建任务或从中间阶段开始时不重新下载、不重复无关检查，也不把旧字段/旧输入的审核结论误用于新数据。

## 8. 建议落地顺序

1. **先固化真实经验和验收清单**：针对当前任务，用人工能判定的小样本形成规则、基准及正确/错误案例。当前5篇文献测试可作为数据提取规则试点；它不替代建模和最终结果的验证。
2. **实现程序规则与证据报告**：把已确认的通用断言自动化，建立逐项结果和差异表。
3. **接入独立复核与人工裁定**：实现A/B分开检查、证据比较、问题闭环及受影响项复验。
4. **最后接下游门禁**：下载交接、建模执行、正式发布读取同一份版本化质量报告，避免只点状态按钮就视为通过。

以上步骤是候选方案。具体规则、容差、审核职责和可接受的例外需讨论后确认；目前没有据此启动新的科学任务或把草案规则写入项目执行配置。

## 10. 下载数据模块：目标与人机分工讨论

### 已明确的目标

研究者2026-10-26原话：**“这部分的目标是对模型输入的基础数据的下载和更新”。**

据此，本模块应以具体模型需要的数据为出发点。必须把人负责的需求和科学判断、智能体负责的执行和可编码核查，以及页面如何提示分别说清楚。以下分工、更新政策和界面均为本轮候选建议，尚未确认或实现。

### 候选分工

| 工作 | 人负责 | 智能体/程序负责 |
| --- | --- | --- |
| 确定模型输入需求 | 在现有下载方案中说明并确认需要的变量及含义、范围、时间/空间尺度、预期单位和必须具备的内容，不另填需求表。 | 直接从已确认方案读取要求；需要时结合已有代码、输入样例整理候选缺口。已明确内容复用，不让研究者重复抄录。 |
| 选择数据来源 | 首次确认数据来源是否适合研究，以及缺失或替代来源的选择。 | 推荐并核对候选来源，解析官方目录与字典，唯一明确的名称匹配自动完成，保留实际依据。 |
| 执行获取 | 处理确实需要本人的登录、验证码或机构权限。 | 根据已确认规则定位文件、选择明确版本、下载/续传、控制频率、核查文件并保存来源；已有同版本有效原件复用。 |
| 例行验收 | 首批核查代表性记录；处理口径歧义、缺口或超出既定规则的问题。 | 比较预期与实际范围、字段、单位、记录数、完整性和已确认基准；给出差异与证据，未检查项不自动通过。 |
| 获取更新 | 事先确认更新政策，对历史改值、来源撤回、分类/单位变化及异常差异作决定。 | 检查来源新版本，下载新增内容或必要的新包，生成新增/修订/删除/结构变化清单，保留旧有效版本。 |
| 交接与启用 | 确认首次验收和例外处理规则，决定何种条件允许自动交接。 | 按获确认的规则形成新批次并交下游；未通过或待处理项不能伪装为正式可用输入。 |

技术信息如官方文件地址、官方代码、版本、真实可用年份和文件大小，应由智能体核对并记录；只有真实歧义或会改变研究范围的决定才交人处理。

### 候选更新政策

1. 旧原始文件、旧输入版本和旧检查证据保留。
2. 官方发布相同版本且本地原件有效时复用；来源无法在下载前确认版本时如实说明，可先取得候选文件再去重，不冒称已经证明无变化。
3. 按批准的范围获取新增时期；例行检查通过后形成新候选批次。
4. 历史值改写、记录撤回、分类/单位/字段含义变化应显示差异，按事先确认的政策处理；政策未定时交人决定，不静默覆盖。
5. 原始数据更新与模型正式输入替换分开记录。清洗、尺度或单位转换、字段对齐及模型输入启用有各自的规则和版本，不因下载成功就自动修改正在使用的模型输入。
6. 重复核查只针对新增、变化及其影响范围；输入和规则未变且证据仍适用的检查复用。

### 映射到现有模块区域的候选内容

以下四项是需要明确的内容分组，应复用现有模块的方案、执行、文件与成果区域，不作为新增四个模块或重建一套页面的要求。当前重点是补齐每个模块运行后的成果审核。

1. **模型输入需求**：统一写在现有下载方案中，审核直接引用该方案。程序可在内部提取要求用于比较，不新增研究者需要填写或单独审批的需求表。
2. **下载与更新规则**：展示来源、筛选、更新范围、历史修订政策、验收条件与人工处理条件。人与智能体的责任标明，不重复索要可自动查到的信息。
3. **执行与待处理**：展示当前步骤和进度，普通技术步骤自动推进。确实需要人时，显示具体对象、原因、证据和需要的一项操作，保留进度。
4. **本次成果与验收**：原始文件、来源清单、预期与实际对比、更新差异、逐项检查报告、待人工事项及可交接状态。

运行状态、质量状态和当前模型启用版本分别显示，避免“下载完成”被误读为“模型输入已验收并替换”。

### 当前讨论的下一项

先确认本模块的人机分工及更新底线，再确定输入需求表和逐项验收规则。暂不要求研究者补官方代码、下载链接或技术配置，不启动下载，也不把上述候选项自动登记为已确认执行规则。

## 11. 讨论澄清：在各现有模块补齐成果审核

研究者2026-10-26指出：**“本次成果与验收 这里是不是就是要审核？现在就是感觉 每个模块都缺少审核的部分”。**

本轮按此要求收敛：沿用现有模块和页面区域，重点补齐运行后的成果审核，不继续增加平行的页面分块。

- **执行前的规则审核**：确认做什么、按什么方法和验收条件执行。
- **执行后的成果审核**：针对本次真实产物，列出检查项、实际结果、证据、未决问题和是否可交接。
- 统一的成果审核呈现可以复用，但具体规则仍逐个模块讨论，不用一份泛化清单冒充所有环节的科学验收。

候选成果审核区包含：本次对象与版本、逐项检查结果、证据、待人工事项、通过/退回/待补充结论及对应交接状态。自动可判定的项目由程序执行；科学口径、例外和需要原件核对的事项交研究者。没有检查过的项目保留“未检查”，不能因点击模块通过就变成已核验。

本轮只是明确缺口及收敛方案，还没有实施统一审核组件、质量门禁或各模块检查器。下一步继续只讨论下载数据模块的审核对象、检查方法、证据及放行条件。

## 12. 下载审核简化：直接核对现有方案

研究者2026-10-26明确：**“与模型输入需求明确对应 这个在方案里应该说明的”**，并提出当前审核设计可能过于复杂。

按此更正，模型输入需求以现有下载方案为唯一人工填写和确认入口；此前额外需求表或独立需求审批的建议不再作为本模块的必要建设项。现有方案若已写清要求，直接使用，不能以缺少新表单为由重复询问或阻止任务。

本模块首期候选审核简化为：

1. **与方案一致**：核对来源、对象、范围、字段和单位口径；不能判定的具体事项才请人解释。
2. **获取完整且可读取**：核对真实下载完成、文件/批次完整、可打开；数据缺口单列原因。
3. **更新变化已说明**：复用未变化的已确认数据，列出新增、历史改值、删除或结构变化；无相应处理规则时交人决定，旧版本保留。

候选界面在现有结果区域给出上述三项的简短结论，详细证据沿用下载记录和可展开明细。通过项收起，突出需处理事项；沿用“确认文件并进入清洗”交接按钮，不再添加一轮重复的人工审核按钮。首次方案确认和已有最终交接仍保留；登录/验证或会改变范围及口径的歧义单独提示。

跨智能体独立复核、复杂质量评分和完整逐项签认仍保留为后续可选讨论方向，不作为首期下载审核的必需流程。首期不在下载阶段擅自执行缺失值填补、异常删除、单位转换或正式模型输入覆盖。

本节记录设计收敛；上述自动核查仍待确认具体条件并实现，未修改运行中的执行逻辑或开始下载。
