# 人工审核工作流（讨论草稿 v0.1）

## 定义

以明确验收标准和证据审阅模块成果，给出通过、退回或待补充决定。既可审核数据/规则/对齐方案，也可审核文献参数和计算结果；审核结论绑定具体成果版本。

## 输入

- 必需：审核对象及版本、来源模块、交付物、检查报告与待审问题。
- 验收标准：明确审核项目、通过条件、抽样方式和需人工判断的事项；缺失时先拟标准并确认。
- 可选：参考数据、原文证据、新旧差异、审核人、历史结论和优先级。

## 执行

1. 确认审核对象、范围和版本，检查材料是否齐全。
2. 将验收标准整理为逐项清单，区分自动检查结果与人工判断项。
3. 展示证据、差异、风险记录和抽样记录，供审核人检查。
4. 由审核人逐项给出决定与理由，记录需要补充的证据。
5. 汇总通过、退回或待补充结论；退回时指定来源模块、问题与复验要求。
6. 修订后审核新版本，保留历史；通过版本交给下游使用。

## 交付

- 审核报告：对象/版本、标准、覆盖范围、逐项结论、证据、审核人和时间。
- 问题清单：严重程度、责任模块、修正要求、状态及复验结果。
- 下游可用的通过版本标识，或待补充/退回决定。

## 检查

- 每个结论有明确标准和证据，未审项不被自动标为通过。
- 抽样范围与局限清晰，抽样通过不被描述成全量逐条审核。
- 成果修改后明确原结论是否仍有效，关键变化触发复验。
- 所有阻断问题关闭后才能按确认政策交付下游；AI 建议与人工最终决定分别记录。

## 异常

- 标准缺失或意见冲突：列出分歧并补齐判定标准。
- 材料/证据不足：标记待补充，返回对应模块。
- 审核对象版本变化：停止沿用旧结论，核对变更范围并重新审核受影响项。
- 未通过：按数据、参数、对齐或代码问题回退，携带可执行的修正要求。

## 需对齐内容

1. 人工审核是否为跨模块能力，还是只在固定流程末尾集中执行？
2. 哪些环节设置强制审核：清洗规则、对齐方案、参数发布、计算结果？
3. 通过/退回/待补充是否足够，是否需要附条件通过？
4. 谁可审核，是否需要多人意见和最终裁定？
5. 抽样比例、阻断等级和版本变更后的复验规则如何确定？
