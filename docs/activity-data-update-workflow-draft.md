# 活动数据更新工作流（讨论草稿 v0.1）

## 定义

将新获取且经清洗的数据与现有活动数据对齐，处理新增、修订和版本变化，生成可进入计算的新活动数据版本。“活动数据”的具体对象与指标由研究任务确定。

## 输入

- 必需：新活动数据及来源/清洗说明、目标计算的输入约定。
- 更新已有数据时：旧数据版本、连接键、时间/地域/对象范围。
- 可选：新增与修订判定、冲突优先级、分类映射、尺度转换、历史回补与验收标准。
- 尚无新数据时，将明确的数据需求交给下载数据和数据清洗，再返回本模块。

## 执行

1. 核对新旧数据覆盖范围、版本与清洗状态。
2. 明确连接键与业务含义，形成字段、分类、单位和时间/空间尺度对齐方案。
3. 按确认规则区分新增、修订、不变和冲突记录；明确源端删除是否应同步。
4. 对齐并合并，保留来源和旧值；对无法映射的记录单独列出。
5. 核对覆盖与数量、汇总差异和时间连续性，经必要审核后形成独立版本。
6. 交给计算，并在需要时固定参数和方法比较更新前后的结果。

## 交付

- 更新后的活动数据及字段字典、版本信息。
- 对齐文档与规则、记录级来源和更新差异。
- 新增/修订/冲突/无法映射清单、覆盖变化与检查报告。
- 可选的计算影响分析及交接说明。

## 检查

- 连接键唯一性和连接基数符合预期，未出现错误扩增或丢失。
- 单位、类别、尺度对齐正确，转换和汇总可追溯。
- 输入与输出数量可核对，时间/地域覆盖及修订范围清晰。
- 新旧差异在验收范围内；通过更新检查的数据具备明确计算输入版本。

## 异常

- 新数据尚未清洗或来源不明：返回下载/清洗环节补齐。
- 分类变更、连接键缺失或尺度不可直接匹配：提出映射方案，交人工确认。
- 新旧值冲突或历史回补：按确认优先级处理，保留冲突证据与修订范围。
- 部分范围未更新或影响异常：标记部分完成，保留旧有效版本，定位后再发布新版本。

## 需对齐内容

1. “活动数据”首期具体指哪些指标和数据对象？
2. 与下载数据的分工是否确定为“获取原始数据”和“对齐合并为计算输入”？
3. 新旧冲突优先级、源端删除与历史修订如何处理？
4. 时间/空间尺度转换、分类映射是否需要人工确认？
5. 部分更新可否进入计算，是否必须做新旧结果比较？
