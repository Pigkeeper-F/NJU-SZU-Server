## 已证实的故障

1. **跨文献续跑标记污染。** 003与004的旧 `pending_url_hash` 均精确对应009的PDF地址。临时 `_request_url` 未在文献边界清空，普通页面检查又覆盖了等待标记。修复后各篇检查使用本篇来源，真正已点击PDF的持久标记不被普通检查覆盖。旧003/004窗口及父窗口已不在浏览器中，核对无已保存PDF、003旧网页正文完整后，备份并仅重置这两篇失效的窗口绑定。
2. **原生PDF预览壳被误判。** 在与实际相同的持久浏览器CDP会话中，本地服务器返回HTTP200和有效66058字节PDF，自动化响应读取却得到601字节HTML预览壳。旧逻辑将其误报为页面错误。新窗口首个PDF响应还可能先于可用frame出现而被漏接；临时附件窗口也可能在查询target时已消失。
3. **人工验证后的衔接缺口。** ScienceDirect在详情页到PDF转换时显示验证码。人工完成验证后，当前页已是原生PDF，旧逻辑仍因无文章DOM而空等。新增严格的保留PDF续跑：校验任务绑定、原父页文献身份、所见PDF入口哈希及当前PDF文档类型，继续保存当前文件。
4. **已观察临时地址过期。** 本轮003/004的签名CDN地址有效期均为300秒。人工验证后，接入新衔接代码所花时间超过有效期；后台保存实际收到403。此处已证实是这些地址过期，不能归因为研究者未登录，也不能推广为所有网站或文件的固定等待时限。

009当时只有笼统的 `page_error` 记录，没有响应正文类型/状态分支，不能断言它必然命中上述哪一条。其可人工下载已由真实文件核验确认，自动获取失败仍如实保留，不算自动下载成功。
