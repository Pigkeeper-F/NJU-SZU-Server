# 全流程实跑指南（九步研究流程）

给第一次上手的人：照着点一遍，①→⑥ 走通。**预计总耗时 15–30 分钟**（免费模型慢，见 §4 时间预算）。

- 流程契约见 `docs/contract.md`（§22 九步主流程 / §23 文献调研与期刊规范 / §24 冷启动·初筛·问题凝练）
- 业务流程的出处：师兄的两阶段九步（阶段一六步 + 阶段二���步）

## 0. 三步准备

### 0.1 重启本地服务（改了代码必须重启）

```bash
cd D:/zcode-work/report/flow-agent-web
# 先停掉旧的 8123 进程，再起新的
netstat -ano | grep ":8123" | grep LISTENING
# 记下 PID 后：taskkill //F //PID <PID>
node server.js
```

看到 `Flow Agent server started: http://localhost:8123` 就成了。**服务只绑本机**（127.0.0.1），
局域网别人访问不到，这是有意的（`.env` 里有 API Key）。

### 0.2 浏览器里改模型

左下角**齿轮** → 「模型」→ 找到 **zcode** 分组（网关 goat）→ 模型填：

```
minimax/minimax-m3.1-flash:free
```

→ 点「测试连通」，看到 `✓ 连通成功` 再走。

> 填 `minimax/minimax-m3.1-flash`（不带 `:free`）会报**额度不足**——付费通道没余额了。
> 浏览器里这份设置存在浏览器本地，服务端 `.env` 是另一份（已同步成 `:free`），两边都要对。

### 0.3 新建一个项目

左侧栏「**当前项目**」右边的 **＋** → 输入项目名 → 确定。
旧项目会自动归档，**不会丢数据**。

## 1. 环节① 文献调研

左侧栏点「**按业务流程初始化 9 个模块**」（在「＋ 添加下一步」下面、「＋ 添加 API」上面）
→ 一次铺满整条九步链（①文献调研 … ⑨校稿核验；其中「数据获取、清洗处理」展开成下载数据+数据清洗两个模块，共 10 个）。

> **当前任务已有模块链时**（比如已经跑着下载数据→数据清洗→计算），点它会提示
> 「当前任务已有流程链…请点顶部『+ 新建任务』」——九步流程要放在一个空任务里，别和旧链混在一起。

> 另一个入口在**空的模块空间**里（同样是这个按钮）。两个入口行为一致：一次铺满九步，
> 之后每过一道审核门就自动补出下一步。

### 1.1 冷启动：把模糊想法变成检索式

在模块空间上方的「**调研面板**」里：

1. 「想法」框写一句你的研究想法（越具体越好，一句就够）：
   `我模糊地想知道：中国北方旱地，长期施肥到底对土壤有机碳有没有影响`
2. 点「**生成检索式**」→ 等 **10–30 秒**

会得到 3 条不同角度的检索式（宽口径 / 聚焦方法 / 聚焦区域），每条下面写明检索意图。
点某条右边的「**用这条**」，检索式就填进上面的输入框了。

> 也可以跳过这步，自己手写检索式。Google Scholar 语法：短语用双引号，`OR` / `AND` 连接，必要时加括号。

### 1.2 检索

点「**检索**」→ 状态行变成「检索中（作业 xxxxxxxx…）」。

- 首次运行会自建 `.venv` 并装 Chromium，**可能要几分钟**；之后再跑就快了。
- Google Scholar 可能弹**验证码**：在自动打开的浏览器窗口里手动过一下，检索会继续。
- 拿到候选后，调研面板下方会列出**候选清单**（标题 / 作者 / 年 / 期刊 / 摘要片段）。

### 1.3 人工初筛（这一步别跳）

候选清单里**勾掉不要读的**，默认全勾。

- 只勾真正相关的 → 省模型调用，也更准；
- 勾选状态在刷新后仍保留（作业 id 记在模块参数上）。

点「**确认初筛并生成要点**」。

### 1.4 抽取要点（等 1–3 分钟）

服务端会：逐篇抽「研究问题 / 数据来源 / 方法 / 结论 / 局限」→ 再横向归纳「共识 / 分歧 / 研究空白」。

产物（面板下方可**直接点链接下载**）：

| 文件 | 内容 |
|---|---|
| `notes.csv` / `notes.json` | 逐篇要点 + 题录 + `evidence`（全文 / 仅题录） |
| `synthesis.md` | 共识与分歧，每条带出处 id |
| `gaps.md` / `gaps.json` | 研究空白清单：空白 + 支撑依据 + 可检验方向 |
| `screening_result.json` | 初筛留档（谁被留、谁被排除、为什么） |

> **重要**：只有题录（没拿到全文）的文献，结论/局限会如实写「文中未说明」——这是设计如此，
> 不是 bug。想要实质结论，就得让管线去抓全文。

### 1.5 过审核门，进②

模块空间顶部的**状态条**：

`○ 待开始` → 点「**完成并提交审核**」→ `⏳ 待审核` → 点「**确定（通过）**」→ 自动跳到下一个模块。

## 2. 环节② 科学问题凝练

### 2.1 生成候选问题

「**问题面板**」里：

1. 「想法」框写你的研究问题（可与①相同）
2. 点「**生成候选问题**」→ 等 **2–4 分钟**（上游不稳时会自动重试，最长约 8 分钟）

会得到 3–5 个候选，每个摊开显示：陈述 / 假设 / 变量（带单位）/ 边界条件 / 对应空白 / 文献依据 / 可行性与卡点。

### 2.2 采用一条

点某条候选右边的「**采用这条**」→ 等 **2–4 分钟** → 出「问题说明书」。

说明书固定七个小节：研究问题 / 可检验形式 / 研究对象与关键变量 / 边界条件 / 与文献空白的对应 /
可行性初判 / 预期贡献。**它会自动写进「环节文档」**（草稿态）。

### 2.3 审核环节文档

在「**环节文档 · 标准与验收的契约**」卡里点「**审核通过**」。

审核通过的文档就是**下游③数据获取与清洗、④模型选择与运行的输入契约**——这才是「衔接」的实际含义。

### 2.4 过审核门，进③

同样：状态条 →「完成并提交审核」→「确定（通过）」→ 出现「下载数据」模块。

## 3. 环节③④⑤⑥（既有能力）

| 环节 | 做什么 | 产物 |
|---|---|---|
| ③ 下载数据 / 数据清洗 | 「数据获取、清洗处理」展开成两个模块；清洗标准用自然语言定，经人工确认 | 清洗后的数据 + 清洗标准文档 |
| ④ 修改计算 | 选计算方式（直接计算 / 修改计算后计算）→ 上传代码与输入数据 → 执行 | 结果数据 + 运行日志 |
| ⑤ 绘图 | 依据问题与数据出图 | 图表文件 + 图注 |
| ⑥ 文章撰写 | 说明卡底部填**目标期刊**（默认 AAAI）→ 对话里起草正文 → 生成代码并执行 `tools/writing_build.py` | `manuscript.tex` / `references.bib` / `build_report.md` |

### ⑥ 的具体操作

1. 说明卡底部「目标期刊」填 `AAAI`（或 NeurIPS / ICML / 其它刊名；留空则按通用结构生成并标注未按期刊约束）
2. 底部输入区默认就是「**✧ AI 对话**」（另一档是「✎ 记录模式」）→ 让它按 AAAI 规范起草正文（它能拿到上游已审核的环节文档与产物清单）
3. 环节文档卡里点「**生成代码并执行**」→ 确认执行（lang 用 python，跑 `tools/writing_build.py` 的逻辑）
4. 产物清单里出现 `manuscript.tex`、`references.bib`、`build_report.md`

> `build_report.md` 里有「写作约束清单」（AAAI 的双盲/摘要词数/篇幅/图表要求）和「待补清单」，
> 以及**模板文件 `aaai26.sty` 是否就位**的提醒——模板要从当年 AAAI Author Kit 下载。

---

> ⚠ **模块助手要切到「API 对话」**：模块空间顶部有个「模块助手」下拉，默认是「本机 Codex」，
> 而本机 Codex 没登录，会红字提示「Codex 服务断开」。①文献调研与②科学问题凝练的**调研面板走的是服务端 API**
> （不依赖这个下拉，照常可用）；但要和助手**对话**追问，就得把下拉切成「API 对话」。

## 4. 时间预算（实测，免费模型）

| 步骤 | 耗时 | 备注 |
|---|---|---|
| 冷启动（生成检索式） | 10–30 s | 一次模型调用 |
| 检索（Scholar） | 30 s – 数分钟 | 首次要装 Chromium；可能遇验证码 |
| 要点抽取 + 归纳 | 70 s（3 篇）/ 2–3 min（9 篇） | 每 3 篇一次模型调用 |
| ②候选问题 | 2–4 min | 免费通道会间歇性失败，服务端自动重试 4 次 |
| ②问题说明书 | 2–4 min | 同上 |
| **①+② 合计** | **约 8–15 分钟** | 免费模型单次调用 2 分钟量级 |

慢是模型的事，不是卡死。状态行会一直显示当前在做什么。

## 5. 排障

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 报「无法连接 AI 服务」 | 浏览器里存着旧的「添加 API」凭证（会覆盖设置里的分组） | 报错括号里会写明**当前配置与来源**（2026-10-21 起）：来源写「浏览器「添加 API」里的凭证」就是这个原因。修法二选一：① F12 → Console 执行 `localStorage.removeItem('research_api_keys_v1'); location.reload();`；② 左侧「添加 API」→ 弹窗里点「**移除已存密钥**」（2026-10-21 新增，原来只能存不能删） |
| 报「额度不足 / insufficient credits」 | 模型填成了付费通道 | 改成 `minimax/minimax-m3.1-flash:free`，点「测试连通」 |
| 报「请从工作台发起请求」 | 直接用 curl 打接口缺 `X-Workbench: 1` 头 | 加上该头；网页里不会遇到 |
| 一直「检索中」不动 | Scholar 弹了验证码 | 在自动打开的浏览器里手动过验证码 |
| ②报「没有研究空白可用」 | ①没跑出空白（模型没归纳出，或还没跑①） | 先完成①并确认「研究空白 ≥ 1 条」 |
| 502 / 稍后重试 | 上游临时不可用 | 服务端已自动重试 4 次；仍失败就等一分钟再点 |
| 刷新后初筛清单没了 | 作业 id 没记上 | 重新检索一次；或检查该模块参数里 `researchJobId` 是否还在 |
| 产物点不开 | 该文件不在作业登记里 | 只有 `research/` 下的文件可下载；别的产物在各自模块的产物区 |

## 6. 不想点网页时的等价命令

```bash
# 冷启动
curl -s -X POST http://127.0.0.1:8124/api/literature/research-plan \
  -H "Content-Type: application/json" -H "X-Workbench: 1" \
  -d '{"idea":"北方旱地长期施肥对土壤有机碳"}'

# 检索 → 候选清单
curl -s -X POST http://127.0.0.1:8124/api/literature/search \
  -H "Content-Type: application/json" -H "X-Workbench: 1" \
  -d '{"config":{"topic":"北方旱地长期施肥对土壤有机碳","query":"(\"long-term fertilization\") \"soil organic carbon\" China","sources":["google-scholar"],"limit":10}}'
curl -s "http://127.0.0.1:8124/api/literature/candidates?id=<jobId>" -H "X-Workbench: 1"

# 初筛 → 要点与空白
curl -s -X POST http://127.0.0.1:8124/api/literature/research-screen \
  -H "Content-Type: application/json" -H "X-Workbench: 1" \
  -d '{"jobId":"<jobId>","keep":["GSC-001"],"exclude":[{"id":"GSC-002","reason":"不相关"}]}'
curl -s -X POST http://127.0.0.1:8124/api/literature/research \
  -H "Content-Type: application/json" -H "X-Workbench: 1" -d '{"jobId":"<jobId>"}'

# ②候选问题 / 问题说明书
curl -s -X POST http://127.0.0.1:8124/api/research/questions \
  -H "Content-Type: application/json" -H "X-Workbench: 1" \
  -d '{"action":"candidates","idea":"...","upstreamJobIds":["<jobId>"]}'
curl -s -X POST http://127.0.0.1:8124/api/research/questions \
  -H "Content-Type: application/json" -H "X-Workbench: 1" \
  -d '{"action":"specify","idea":"...","choice":<候选对象>,"upstreamJobIds":["<jobId>"]}'
```

产物落盘位置：`<项目>/.workbench/literature/<jobId>/research/`。
