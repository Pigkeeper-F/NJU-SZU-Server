# 接收后的校稿核验工作流（讨论草稿 v0.1）

> 九步研究流程 · 环节⑨（第二阶段第三步，末环节）。对应业务流程表「接收后的校稿核验：
> 检查出版校样中的文字、数据、图表等是否准确」。
> 上游是环节⑧定稿的稿件与其修改记录。

## 定义

拿到出版方的校样后，逐项核对校样与终稿的差异——文字、数字、图表、编号与引用、
作者与出版信息——把需要勘误的地方挑出来并给出确认或勘误清单，保证见刊版与终稿一致。

## 输入

- 必需：出版方校样（PDF）；终稿源文件（`manuscript.tex` / `manuscript.md`）；
  图表源文件与结果数据；本轮全部修改记录。
- 可选：出版方给出的勘误期限、期刊的勘误流程与费用规则、上一版校样（若有多轮）。
- 校样与终稿不是同一版本时，先定位版本差异再核验，不直接比对。

## 执行

1. 版本对齐：确认校样对应的投稿版本（稿件号 / 版本标识）与终稿一致，登记校样文件与日期。
2. 文字核对：逐段比对校样与终稿正文，标出出版方改动、截断、丢字、错别字与格式异常。
3. 数字核对：正文中的每个数字与图表数据、结果文件比对，标出不一致。
4. 图表核对：图表是否齐全、编号与正文引用是否对应、坐标轴单位与图注是否被改、
   分辨率与颜色是否满足印刷要求、图位置是否合理。
5. 编号与交叉引用核对：公式、表格、附录、参考文献编号是否连续且指向正确。
6. 元数据核对：作者姓名与顺序、单位与地址、通讯作者、基金与资助号、致谢、
   版权与许可声明、注册号或伦理号、投稿日期与出版日期栏。
7. 汇总勘误清单：每条含位置（页/段/图号）、校样现状、建议改法、严重级别。
8. 出确认函草稿：无勘误则出确认；有勘误则区分「须勘误」与「可接受差异」。
9. 归档最终包：终稿、校样、勘误清单、确认函、图表源文件与数据。

## 交付

- 校样差异核对表：逐项位置、类型、严重级别、建议改法。
- 勘误清单（可直接提交出版方的格式）。
- 确认函草稿（无勘误时为确认，有勘误时为勘误说明）。
- 印刷可行性提示：分辨率、颜色模式、字号与留白问题。
- 归档包：终稿源文件、校样 PDF、图表源文件、结果数据、勘误记录。

## 检查

- 校样与终稿是同一版本，核对基线明确。
- 正文全部段落已逐段核对，出版方改动均已记录（改动本身不等于错误）。
- 正文数字与结果数据、图表完全一致。
- 图表齐全、编号与引用对应、单位图注未被破坏。
- 作者、单位、基金、致谢、版权、声明信息与终稿一致。
- 勘误清单每条可执行：写明改什么、改成什么、在哪一页。
- 确认函与勘误清单口径一致，不出现「无问题」与「有勘误」矛盾。

## 异常

- 校样与终稿版本对不上：停下，向出版方确认对应版本后再核。
- 出版方改动导致结论表述变化：按实质影响处理，必要时撤回或更正。
- 发现关键数字被改动：以结果文件为准，立即列为必改勘误，并同步告知导师。
- 图表在印刷稿中不可读：给出重制建议（分辨率 / 配色 / 尺寸），不勉强接受。
- 勘误期限紧：先处理影响结论与可复现性的项，其余标注延期。
- 期刊不支持事后勘误：改为发布更正说明或补充材料，方案交人工决定。

## 需对齐内容

1. 校样以什么形式拿到（PDF 附件 / 投稿系统下载 / 邮件），决定解析方式。
2. 数字核对是逐个核对还是限定关键数字（结果表 + 摘要 + 结论）。
3. 勘误清单的提交方式与格式（是否由本环节直接生成可提交文件）。
4. 是否需要同时产出「出版方改动摘要」供团队知悉（改动本身未必是错误）。
5. 见刊 PDF 是否也需要一次自动核验（与校样同流程）。
