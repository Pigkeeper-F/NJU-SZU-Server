# 调试台（Debug Toolkit）

> 出问题时不用猜，也不用截图来回传。
> 配套契约：`docs/contract.md` §25。

## 1. 它解决什么问题

这套工具是为「**界面看起来没反应 / 报了个看不懂的错**」这类问题准备的。开发期踩过的三个真实坑，都能靠它一分钟定位：

| 现象 | 真实原因 | 靠什么定位 |
|---|---|---|
| 点了「生成检索式」，界面毫无变化 | `render()` 的增量快速路径把面板状态变化吞了（面板状态没进重绘签名） | 看「最近请求」里**有没有**那个 POST：有请求但界面不变 → 前端渲染问题；没请求 → 按钮没绑上 |
| 检索式显示成每行一个字符的 JSON 碎片 | CSS 的 flex 容器没开 `flex-wrap`，说明文字的 `100%` 基准把检索式挤成 0 宽 | 看错误明细 + 页面 DOM |
| AI 对话报「无法连接 AI 服务」，但「测试连通」是通的 | 浏览器里残留的「添加 API」旧凭证覆盖了设置里的分组 | 看响应里的 `config.source`：写 `browser-credential` 就是它 |

## 2. 两种用法

### 2.1 命令行（维护者日常用这个）

```bash
node tools/debug-report.js                # 默认连本机 8123
node tools/debug-report.js --port 8124     # 指定端口
node tools/debug-report.js --limit 40     # 看更多记录（默认 30）
node tools/debug-report.js --json         # 原始 JSON，便于程序化处理
```

输出是中文摘要，一屏看完：服务状态与运行时长、`.env` 模型与网关、Key 有无、文献作业数、
请求/错误计数、**失败请求清单**（HTTP ≥ 400）、**慢请求清单**（≥ 3s）、**错误明细**（含堆栈）、
最近 15 条请求。

### 2.2 调试页（想用眼睛看时）

<http://localhost:8123/debug.html>（或任意任务页面地址栏加 `?debug=1` 后从侧栏点「调试台」）。

页面给出：服务状态卡片、错误表、最近请求表，**3 秒自动刷新**。

> 侧栏的「调试台」链接**默认不出现**——这个页面主要是给维护者（AI）用的，
> 不想在正常使用的主界面里占位置。页面本身没有删除，随时可开。

## 3. 采集范围与边界

服务端在内存里维护一个**环形缓冲**（上限 200 条，进程重启即清空，**不落盘**）：

- 每个 `/api/…` 请求一行：`{ seq, at, level, kind, method, path, status, ms }`
  （`level=error` 的行额外带 `error` / `stack` 摘要）
- `process.on('uncaughtException' | 'unhandledRejection')` —— **只记录不退出**，
  本地开发工具必须一直活着
- 前端 JS 错误（`window.onerror` / `unhandledrejection`）由主页面自动上报

**边界**（写在这里是为了不被误用）：

- **不含请求体**：不记录你发出去的内容
- **API Key 一律脱敏**：`Bearer ***` / `apiKey=***`
- 服务**只绑 127.0.0.1**，同网段访问不到
- 日志**不落盘**、不外传，只在本机内存里

## 4. 端点

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/debug/state?limit=` | GET | 服务状态、运行时长、Node 版本、`.env` 模型、文献作业数、错误计数、最近请求与错误 |
| `/api/debug/logs?limit=` | GET | 原始日志数组 |
| `/api/debug/client-error` | POST | 前端 JS 错误上报 `{ where, message, stack }` |

`js/debug.js` 的联网权限**仅限 `/api/debug/*` 只读**（已登记在契约自检的联网白名单里）；
`debug.html` 是独立工具页，**不进 `index.html` 的脚本列表**，不影响主界面。

## 5. 排查手册

拿到诊断报告后按现象查：

| 看到什么 | 意思 | 怎么办 |
|---|---|---|
| 错误明细里有 `client-error` | 前端 JS 抛异常了，堆栈在 `stack` 字段 | 照堆栈定位；若指向某个渲染函数，多半是「状态变了但没触发重绘」——检查该状态是否进了 `docSigOf()` |
| 错误明细里有 `uncaughtException` | 服务端代码抛了未捕获异常 | 看堆栈第一行定位文件；这类错误服务端会继续跑，但功能多半已经坏了 |
| 失败请求里大量 502 + `无法连接 AI 服务` | 上游模型通道不可用（拥塞 / 额度 / 凭证被覆盖） | 看 `.env 模型` 与「当前模型」两张卡片；`source=browser-credential` 说明浏览器里的旧凭证在盖住设置 |
| 慢请求里 `/api/literature/research*` 超过 3s | 模型通道慢（免费通道常见 1–4 分钟） | 正常现象，界面有进度条与取消按钮；持续失败就是通道拥塞，换模型或等恢复 |
| 失败请求里 400 + `没有研究空白可用` | 环节①没产出空白，或还没跑① | 先在①完成调研并确认「研究空白 ≥ 1 条」 |
| 失败请求里 403 `请从工作台发起请求` | 直接用 curl 打了接口、缺 `X-Workbench: 1` 头 | 网页里不会遇到；命令行自测请带该头 |
| 「累计请求」在涨但界面不动 | 状态变了没触发重绘 | 检查该状态是否已纳入 `docSigOf()` 的签名 |

## 6. 维护约定

- **加新能力时**：若引入了新的模块级瞬态状态，**必须把它加进 `js/chat.js` 的 `docSigOf()`**，
  否则状态变化会被增量快速路径吞掉，表现为「点了没反应」——这是本项目踩过两次的坑。
- **加新端点时**：若它可能出错，请在 `handleXxx` 的 catch 里把错误摘要 `debugRecord` 一条，
  调试台就能直接看到。
- **不要把请求体、密钥、用户文件内容写进日志**；`debugSafe()` 会做基础脱敏，但调用方要自觉。
- **模型输出永远当作不可信输入**：免费模型经常不按格式输出，解析层要假设 JSON 会坏，
  并准备正则 / 按行的兜底（见 `tools/research-question.js` 的三层兜底）。
