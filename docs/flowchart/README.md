# 业务流程图 · 流程智能体（两阶段主流程 + 数据/参数流水线 + 计算竖图）

由业务说明整理出的可编辑流程图（draw.io 源文件 + 渲染产物），用于设计智能体的能力节点。

## 图里有什么

**上半区 · 两阶段主流程**
- **阶段一 · 研究写作过程（6 步）**：① 文献调研 → ② 科学问题的凝练与提取 → ③ 数据获取、清洗处理 → ④ 模型的选择与运行 → ⑤ 图表的绘制 → ⑥ 文章的撰写和修改
- **阶段二 · 投稿—审稿—发表过程（3 步）**：⑦ 投稿前的全流程校验与投稿 → ⑧ 回复评审意见与最终校验 → ⑨ 文章接收后校稿阶段的校验

**下半区 · 能力节点（v4 布局）**

左侧竖排两条流水线，右侧计算竖图，底部独立一行结果审核：

- **数据流水线 · 活动数据**：下载更新数据（活动数据）→ 数据清洗（自然语言确定清洗标准；不同类型不同方法）→ ◇人工审核：验收标准通过？（未通过 → 更新清洗与验收标准）
- **参数流水线 · 参数与文献**（在数据流水线**下方**）：更新参数数据 → 文献数据挖掘（威源的完整流程）→ ◇人工审核：确定验收标准（未通过回流，机制同款）
- **两条流水线各出一条箭头汇入计算**，标签为「活动数据」「参数数据」——即参数模块纳入计算输入
- **计算（竖图）**：一个计算模块，**分支为两种方式**
  - **1. 直接计算**：计算方法不变，直接改 input 得到结果 → 输出数据
  - **2. 接入模块后**：数据对齐（自然语言形成对齐文档 + 人工审核）→ 对齐方法写成代码 → 运行计算 → 输出数据
  - 两种方式共用同一套计算方法
- **底部 · 结果审核与回退**：◇人工审核：结果是否存在问题？→ 有问题 → 自动定位（数据 / 对齐 / 运行代码）→ 查看更新清洗与验收标准；定位到数据问题 → 回退流水线，定位到对齐 / 代码问题 → 回退计算

图例：蓝框 = 智能体自动执行；橙菱形 = 人工审核/判断；绿框 = 输出；紫框 = 定位与诊断；灰虚线 = 未通过 / 定位后的回退路径。

## 两处业务理解的确认（v3 起沿用）

| 说法 | 判定 | 依据 |
|---|---|---|
| 计算有两种方式：直接计算 / 接入模块后 | ✅ 成立 | 原表「计算」下先写"方法不变，直接改 input 得到结果"；紧接"接入新模块："再写"数据对齐 → 对齐方法写成代码 → 运行计算"。差别就在「对齐」这一步，也正对应审核时"自动定位（数据、对齐、运行代码）"的三层 |
| 参数模块最终纳入计算 | ✅ 合理，但**属推断** | 原表未明写"参数数据进入计算"，是从"直接改 input 得到结果"推出来的；图上用汇合箭头明确表达 |

## 编辑与重新导出

```bash
# ① 改内容：编辑 build_process_chart.py 后重新生成源文件
python build_process_chart.py

# ② 导出产物（Windows 桌面版路径示例）
DRAWIO="C:/Users/33477/AppData/Local/Programs/draw.io/draw.io.exe"
"$DRAWIO" -x -f png -e -s 2 -b 10 -o render/flow-agent-process.drawio.png flow-agent-process.drawio
"$DRAWIO" -x -f pdf -e -o render/flow-agent-process.pdf flow-agent-process.drawio

# ③ 预览
python render_previews.py
```

**四个坑（脚本/文档里都已记录）**

1. draw.io CLI 的 `-x` 是按**内容边界**裁剪（不是页面边界）：页面坐标 → PNG 像素换算必须先求内容左上角（沿父链累加容器偏移，且只统计 `vertex`——`edge` 的 `mxGeometry` 没有 x/y）。
2. 容器标题这类文本若漏传 `parent`，会全部堆在页面左上角叠成一团；自动生成的 id 前缀别与步骤框 id 撞车（会出现重复 id）。
3. **跨容器连线的 id 必须与容器真实 id 完全一致（含大小写）**：容器 id 由脚本生成时若写成 `nodea` 而连线引用 `nodeA`，会变成"悬空引用"——连线直接不渲染（本次 v4 踩过一次，校验脚本已加入引用完整性检查）。
4. 生成的 PDF 若被桌面端/浏览器预览占用会写不进去（`Error writing to file` / `Device or resource busy`）：导出到临时名再覆盖；本地可能出现两个 PDF 名，以内容较新的那个为准。

## 排版提示（给投稿用）

- 出图约 1240×1050 pt（页面 1720×1420 单位，导出按内容边界缩放）
- 正文实测约 11.5pt / 小字 9.3pt / 标题 21.6pt
- 放进 A4 横向正文宽（约 24cm）还会再缩约 0.55 → 正文约 6.3pt（多数期刊要求 ≥6pt，"能看"但偏小）
- 若目标是**双栏论文的单栏**，建议拆成「主流程图」和「能力节点图」两张分别排版

## 待业务确认

1. **「参数数据进入计算」是否为正式设计**（v3 起按推断画入）。
2. **阶段二是否补「评审结果」分支**：现为直线 ⑦→⑧→⑨；现实中评审结果有 接收/小修/大修/拒稿，后两者应打回阶段一 ⑥ 返修再投。
3. **方式二的「数据对齐」是否还包含"接入新模块"的注册动作**（登记模块类型、写校验规则），还是仅做字段/语义对齐。
4. **流水线人工审核的措辞**：原表是"审核（确定验收标准）"（定义动作），图上菱形写的是"验收标准通过？"（判断动作）——若要严格照原文，可改成菱形内写"人工审核：确定验收标准"，分支箭头另标"通过 / 未通过"。
